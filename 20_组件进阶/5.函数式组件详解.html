Functional Components - 轻量、高效的组件形态

💡 什么是函数式组件？

函数式组件是没有状态（data）、没有实例（this）的组件。 它只接收props，纯粹地根据 props 渲染输出，类似于 JavaScript 的纯函数。

📐 公式：函数式组件 = props ➜ VNode（虚拟DOM）
🔍 函数式组件 vs 普通组件
特性 普通组件 函数式组件
data 数据 ✅ 有状态（响应式） ❌ 无状态（只接收 props）
this 实例 ✅ 有实例（this） ❌ 无实例（无 this）
生命周期 ✅ 完整的生命周期钩子 ❌ 无生命周期钩子
响应式系统 ✅ 参与响应式系统 ❌ 不参与（更轻量）
性能 ⭐⭐⭐ 标准 ⭐⭐⭐⭐⭐ 更快（少30%+开销）
使用场景 复杂交互、有状态 纯展示、包装器、列表项

💻 函数式组件定义
// 方式1：对象式定义（带 functional: true） Vue.component('functional-heading', { // ⭐ 关键：声明为函数式组件 functional: true, // props 和普通组件一样 props: { level: Number, text: String }, // 渲染函数，接收 (h, context) 参数 // h: createElement 函数 // context: 上下文对象（包含 props、children、slots 等） render(h, context) { // 根据 level 渲染不同的标题标签 const tag = 'h' + context.props.level; return h(tag, context.props.text); } }); // 方式2：单文件组件中使用 functional 属性 // <template functional> // <h1>{{ props.text }}</h1> // </template>
💡 context 上下文对象

函数式组件没有 this，所有数据通过 context 参数访问：

  • context.props - 接收的 props
  • context.children - 子节点（VNode 数组）
  • context.slots - 插槽函数
  • context.scopedSlots - 作用域插槽
  • context.data - 传递给组件的整个数据对象
  • context.parent - 父组件实例
  • context.listeners - 事件监听器对象
  • context.injections - 注入的数据

// 函数式卡片包装器 Vue.component('card-wrapper', { functional: true, props: { title: String, icon: String }, render(h, context) { // 从 context 中解构 props 和 children const { props, children } = context; return h('div', { class: 'item-box' }, [ // 标题栏 h('div', { style: { fontWeight: 'bold', fontSize: '1.2em', marginBottom: '10px', color: '#667eea' } }, [ props.icon + ' ' + props.title ]), // 内容区域（渲染 children） h('div', children) ]); } });

  • 常用于包装器组件（Wrapper Components）

// 1. 具名插槽示例 Vue.component('layout-wrapper', { functional: true, render(h, context) { // context.slots() 返回插槽函数对象 const slots = context.slots(); return h('div', { style: { border: '2px solid #667eea', borderRadius: '8px' } }, [ // 渲染具名插槽 slots.header, // header 插槽 slots.default, // 默认插槽 slots.footer // footer 插槽 ]); } }); // 2. 作用域插槽示例 Vue.component('list-item', { functional: true, props: ['item'], render(h, context) { // scopedSlots 是作用域插槽对象 const scopedSlots = context.scopedSlots; return h('div', { class: 'item-box' }, [ // 调用作用域插槽，传入数据 scopedSlots.default ? scopedSlots.default({ item: context.props.item }) : context.props.item.name ]); } });

🎯 智能列表包装器

💻 智能列表实现
// 智能列表包装器（函数式组件） Vue.component('smart-list', { functional: true, props: { items: { type: Array, default: () => [] }, emptyText: { type: String, default: '暂无数据' } }, render(h, context) { const { props, scopedSlots } = context; // 如果没有数据，显示空状态 if (!props.items || props.items.length === 0) { return h('div', { style: { padding: '40px', textAlign: 'center', color: '#999', background: '#f5f5f5', borderRadius: '8px' } }, [ h('div', { style: { fontSize: '3em' } }, '📭'), h('div', { style: { marginTop: '10px' } }, props.emptyText) ]); } // 有数据时，渲染列表 return h('div', [ // 统计信息 h('div', { style: { marginBottom: '15px', padding: '10px', background: '#e3f2fd', borderRadius: '5px' } }, `共 ${props.items.length} 条数据`), // 渲染每一项 props.items.map(item => { return scopedSlots.item ? scopedSlots.item({ item }) : h('div', JSON.stringify(item)); }) ]); } });
✅ 这个案例展示了函数式组件的优势
  • ✅ 纯展示逻辑：根据 props.items 渲染，无需内部状态
  • ✅ 高性能：列表项很多时，函数式组件显著提升性能
  • ✅ 灵活的插槽：支持作用域插槽，自定义每项的渲染
  • ✅ 智能空状态：自动判断并显示空状态提示
  • ✅ 轻量级：无实例、无响应式，非常轻量

❌ 何时不应该使用函数式组件？

不适合的场景

  • 需要响应式数据（data）
  • 需要内部状态管理
  • 需要生命周期钩子
  • 需要使用 ref 访问
  • 需要使用 computed 或 watch
  • 需要复杂的事件处理

应该用普通组件

  • 表单输入组件
  • 可交互的复杂组件
  • 需要缓存（keep-alive）的组件
  • 需要在组件内发送请求
  • 需要定时器或副作用
  • 业务逻辑复杂的组件
🎓 面试常考题（5题）
❓ 问题 1：什么是函数式组件？它有什么特点？

答案：

函数式组件是无状态（没有 data）、无实例（没有 this）的组件。特点包括：

  1. 声明方式：设置 functional: true
  2. 无状态：没有 data、computed、watch
  3. 无实例：没有 this，不能使用 this.$emit 等
  4. 无生命周期：没有 created、mounted 等钩子
  5. 高性能：渲染开销比普通组件小 30%-40%
  6. 纯函数：相同的 props 总是产生相同的输出
❓ 问题 2：函数式组件的 context 参数包含哪些属性？

答案：

属性 说明
context.props 接收的 props 对象
context.children VNode 子节点数组
context.slots() 插槽函数，返回具名插槽对象
context.scopedSlots 作用域插槽对象
context.data 传递给组件的完整数据对象
context.parent 父组件实例引用
context.listeners 事件监听器对象（v-on）
context.injections 通过 inject 注入的数据
❓ 问题 3：函数式组件为什么性能更好？

答案（5个原因）：

  1. 无实例创建开销：不需要 new Vue() 创建组件实例
  2. 无响应式系统：不需要使用 Object.defineProperty 将 data 转为响应式
  3. 无生命周期：不需要初始化和调用生命周期钩子
  4. 无上下文绑定：不需要绑定 this 上下文
  5. 直接渲染：直接调用 render 函数生成 VNode，跳过很多中间步骤

性能提升：在大量渲染场景下，性能提升 30%-40%

❓ 问题 4：函数式组件和普通组件如何选择？

答案：

✅ 用函数式组件
  • 纯展示组件（只根据 props 渲染）
  • 包装器组件（如布局容器）
  • 列表项组件（大量渲染）
  • 无交互、无状态
  • 性能要求高的场景
✅ 用普通组件
  • 需要内部状态（data）
  • 需要生命周期钩子
  • 需要响应式数据
  • 需要使用 ref 访问
  • 业务逻辑复杂

记忆口诀：纯展示用函数式，有状态用普通 ✅

❓ 问题 5：函数式组件可以使用 v-model 吗？

答案：

❌ 不能直接使用 v-model，原因如下：

  1. v-model 需要组件响应 input 事件并更新 value prop
  2. 函数式组件没有实例，不能使用 this.$emit()
  3. 函数式组件无状态，不能维护内部 value

替代方案：

// 通过 context.listeners 手动监听事件 render(h, context) { return h('input', { domProps: { value: context.props.value }, on: { input(event) { // 触发父组件的监听器 context.listeners.input(event.target.value); } } }); }

结论：需要 v-model 的表单组件应使用普通组件 ✅

✅ 函数式组件最佳实践
1️⃣ 优先考虑性能敏感场景
// ✅ 好的使用场景：大列表的列表项 Vue.component('list-item', { functional: true, props: ['item'], render(h, ctx) { return h('div', ctx.props.item.name); } }); // 在父组件中渲染1000+项 // <list-item v-for="item in largeList" :key="item.id" :item="item" />
2️⃣ 善用 context.data 继承属性
// 包装器组件时，使用 context.data 继承所有属性和事件 Vue.component('wrapper', { functional: true, render(h, context) { return h('div', { // 继承父组件传递的所有 class、style、attrs、on 等 ...context.data, class: [context.data.class, 'wrapper'] }, context.children); } });
3️⃣ 命名规范

建议在函数式组件名称中体现其特性：

  • functional-xxx - 明确标识为函数式组件
  • 或使用 Pure 前缀：PureListItem
  • 文件名：FunctionalButton.vue 或 Button.functional.vue
4️⃣ 配合 v-once 进一步优化
// 对于完全静态的内容，结合 v-once 使用 // <functional-header v-once /> // 组件只渲染一次，永不更新
🎯 核心总结
  1. 定义：函数式组件 = 无状态 + 无实例 + 纯渲染函数
  2. 声明：设置 functional: true
  3. 参数：render(h, context)，通过 context 访问 props/slots/listeners 等
  4. 性能：比普通组件快 30%-40%（无实例、无响应式）
  5. 适用场景：纯展示、包装器、列表项、高阶组件
  6. 不适用：需要状态、生命周期、v-model、复杂交互
