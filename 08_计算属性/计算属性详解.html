Demo 1: 什么是计算属性？
定义：要用的属性不存在，需要通过已有属性计算得到
原理：底层使用Object.defineProperty的getter/setter
特点：
  • ✅ 有缓存机制，依赖数据不变时不会重新计算
  • ✅ 依赖数据变化时自动更新
  • ✅ 在模板中像普通属性一样使用，不需要加括号
  • ✅ 比methods效率更高（有缓存）

Demo 2: 统计类计算属性 ⭐ 最常用
应用场景：任务管理系统中的统计信息（总数、完成数、完成率等）
核心思路：基于数组的filter、reduce等方法进行统计计算
优势：数据变化时自动更新，无需手动计算

Demo 3: 过滤类计算属性 ⭐ 非常常用
应用场景：任务筛选、商品筛选、搜索过滤等
核心思路：根据筛选条件动态返回过滤后的数组
优势：不修改原数组，声明式编程，代码清晰

Demo 4: get/set 双向计算属性 ⭐ 高级用法
应用场景：全选功能、表单联动、单位转换等
get：读取时调用，用于计算返回值
set：修改时调用，用于更新依赖的数据
典型案例：任务管理系统中的"全选"复选框

全选功能示例

{{ task.title }}
// 双向计算属性 - 全选功能实现 computed: { allChecked: { // get：读取allChecked时调用 // 当所有任务都完成时返回true，否则返回false get() { return this.tasks.length > 0 && this.tasks.every(task => task.completed); }, // set：修改allChecked时调用（勾选全选框时） // value是新的值（true或false） set(value) { // 将所有任务的completed设置为value this.tasks.forEach(task => { task.completed = value; }); } } } // 模板中使用（就像普通的data属性） <input type="checkbox" v-model="allChecked">
💡 理解get/set工作流程：
读取时（显示状态）：
1. Vue读取allChecked → 调用get函数
2. get检查所有任务是否都完成 → 返回true/false
3. 复选框显示对应状态

修改时（点击全选框）：
1. 用户点击复选框 → v-model尝试修改allChecked
2. Vue调用set函数，传入新值（true/false）
3. set函数遍历所有任务，修改completed属性
4. 任务状态变化 → 触发get重新计算 → 复选框状态更新
Demo 5: 依赖链计算属性
概念：一个计算属性可以依赖另一个计算属性
特点：Vue会自动追踪依赖关系，任何一个依赖变化都会触发更新
应用：复杂数据处理、多级统计等

Demo 6: computed vs methods 性能对比 ⭐ 重要
核心区别：computed有缓存机制，methods没有
缓存机制：computed只在依赖数据变化时才重新计算，多次访问使用缓存结果
性能差异：在模板中多次使用时，computed效率远高于methods

计算属性 vs Methods vs Watch 对比

特性 Computed 计算属性 Methods 方法 Watch 侦听器
缓存 ✅ 有缓存机制 ❌ 无缓存 ❌ 无缓存
使用方式 像属性一样使用（不加括号） 必须加括号调用 监听数据变化
返回值 必须有return 可选 无return
适用场景 基于已有数据计算新数据 事件处理、复杂操作 数据变化时执行异步操作
性能 ⭐⭐⭐⭐⭐ 最高 ⭐⭐⭐ 一般 ⭐⭐⭐⭐ 较高

✅ 计算属性最佳实践

1. 统计类计算属性（最常用⭐⭐⭐⭐⭐）
- 总数、完成数、未完成数
- 平均值、最大值、最小值
- 完成率、百分比等

2. 过滤类计算属性（非常常用⭐⭐⭐⭐⭐）
- 根据条件筛选列表
- 搜索功能
- 多条件组合过滤

3. 格式化类计算属性（常用⭐⭐⭐⭐）
- 日期格式化
- 货币格式化
- 文本处理（大小写转换、截取等）

4. 状态判断类计算属性（常用⭐⭐⭐⭐）
- 是否全选
- 是否有数据
- 表单验证状态

5. 依赖链计算属性（高级用法⭐⭐⭐）
- 计算属性依赖其他计算属性
- 多级数据处理

⚠️ 注意事项

1. 计算属性中不要修改依赖的数据
计算属性应该是纯函数，只做计算不做修改

2. 计算属性内部不要做异步操作
异步操作应该使用watch或methods

3. getter应该是无副作用的
不要在getter中发送HTTP请求、修改DOM等

4. set方法是可选的
大多数计算属性只需要getter，只有双向绑定场景才需要setter
