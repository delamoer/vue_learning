⚙️ 27-5 环境变量与模式

1. 为什么需要环境变量？

不同环境（开发/测试/生产）需要不同的配置：

配置项开发环境测试环境生产环境
API 地址http://localhost:3000https://test-api.comhttps://api.com
调试日志开启开启关闭
Mock 数据开启关闭关闭
Source Map完整完整关闭

如果把这些值写死在 JS 里，每次部署前都要手改代码 → 非常容易出错。
环境变量让你将环境相关的配置独立出来，代码与配置分离。

2. .env 文件规则

.env ← 所有模式都加载（优先级最低） .env.local ← 所有模式，但不提交 Git（个人配置） .env.development ← 仅 development 模式（npm run serve） .env.development.local ← 仅 development，不提交 Git .env.production ← 仅 production 模式（npm run build） .env.production.local ← 仅 production，不提交 Git .env.staging ← 自定义模式（npm run build --mode staging）

优先级规则（高覆盖低）

最高： .env.{mode}.local （本地专用，Git 忽略）

次之： .env.{mode} （模式专用）

最低： .env.local 和 .env （通用基础配置）

3. 变量命名规则 ⚠️ 重要

只有 VUE_APP_ 前缀的变量才会暴露给客户端代码！
其他变量（如 SECRET_KEY）即使写在 .env 文件里，也不会注入到 Vue 代码中， 只在 vue.config.js（Node.js 进程）中可访问。 
# .env.development
NODE_ENV=development

# ✅ 以 VUE_APP_ 开头 → 注入到客户端代码
VUE_APP_API_BASE_URL=http://localhost:3000/api
VUE_APP_APP_TITLE=我的应用（开发版）
VUE_APP_ENABLE_MOCK=true
VUE_APP_LOG_LEVEL=debug

# ❌ 不以 VUE_APP_ 开头 → 仅在 vue.config.js 中可用
WEBPACK_PORT=8081
DB_PASSWORD=secret123
# .env.production
NODE_ENV=production

VUE_APP_API_BASE_URL=https://api.example.com
VUE_APP_APP_TITLE=我的应用
VUE_APP_ENABLE_MOCK=false
VUE_APP_LOG_LEVEL=error

4. 在代码中使用环境变量

// src/api/index.js — 根据环境变量配置 axios
import axios from 'axios'

const http = axios.create({
  // ⭐ 读取环境变量
  baseURL: process.env.VUE_APP_API_BASE_URL,
  timeout: 10000
})

export default http

// -----------------------------------------------
// src/utils/logger.js — 根据日志级别控制输出
const LOG_LEVEL = process.env.VUE_APP_LOG_LEVEL || 'error'

export const logger = {
  debug(...args) {
    if (LOG_LEVEL === 'debug') console.log('[DEBUG]', ...args)
  },
  info(...args) {
    if (['debug', 'info'].includes(LOG_LEVEL)) console.info('[INFO]', ...args)
  },
  error(...args) { console.error('[ERROR]', ...args) }
}
<!-- 在模板中也可以直接使用（通过计算属性） -->
<template>
  <div>
    <span>版本: {{ appVersion }}</span>
    <span v-if="isDev" class="dev-badge">DEV</span>
  </div>
</template>

<script>
export default {
  computed: {
    appVersion() { return process.env.VUE_APP_VERSION },
    isDev() { return process.env.NODE_ENV === 'development' }
  }
}
</script>

5. Vue CLI 内置变量

变量名值来源
process.env.NODE_ENV'development' / 'production' / 自定义Vue CLI 自动设置
process.env.VUE_APP_*你在 .env 文件中定义的.env 文件
process.env.BASE_URL与 vue.config.js 中的 publicPath 相同Vue CLI 自动设置

6. 自定义模式（多环境部署）

除了默认的 development 和 production，你可以创建自定义模式（如 staging、uat）。

# .env.staging — 测试/预发环境
NODE_ENV=production        # ⭐ 注意：这里设置 production，让代码做生产优化
VUE_APP_API_BASE_URL=https://staging-api.example.com
VUE_APP_APP_TITLE=我的应用（staging）
VUE_APP_ENABLE_MOCK=false
// package.json — 在 scripts 中指定 --mode
{
  "scripts": {
    "serve":          "vue-cli-service serve",
    "build":          "vue-cli-service build",
    "build:staging":  "vue-cli-service build --mode staging",
    "build:prod":     "vue-cli-service build --mode production"
  }
}
# 使用
npm run build:staging     → 加载 .env.staging（打出 staging 包）
npm run build             → 加载 .env.production（打出生产包）

7. .env 文件的 Git 管理

安全原则： 含敏感信息（密码、密钥）的 .local 文件必须加入 .gitignore， 而 .env.development、.env.production 通常应该提交到 Git（填入无敏感的配置）。 
# .gitignore
*.local           # 忽略所有 .local 文件（含个人密钥、密码）

# 以下文件提交 Git（不含敏感信息）
# .env
# .env.development
# .env.staging
# .env.production

# 如果生产环境配置敏感，用 .env.production.local（不提交）
# 在 CI/CD 中通过环境变量注入

CI/CD 最佳实践： 在 GitHub Actions / Jenkins 等 CI 工具中， 通过 Secrets 配置生产环境变量，在构建时动态生成 .env.production.local， 不需要把真实密钥提交到代码仓库。
