🔄 .sync 修饰符详解

双向绑定的语法糖 - 让子组件更新父组件数据

💡 什么是 .sync 修饰符？

.sync 修饰符是一个语法糖，用于在父子组件之间实现双向绑定。

🎯 为什么需要 .sync？

  • ✅ 简化父子组件通信：避免写繁琐的 @update:xxx 事件
  • ✅ 语义清晰：明确表示这是一个双向绑定
  • ✅ 代码简洁：一行代码替代多行事件监听
  • ✅ 常用场景：对话框显示状态、表单值同步等

📦 .sync 的原理

// 使用 .sync（语法糖）
<child-component :visible.sync="isVisible"></child-component>

// 等价于（完整写法）
<child-component 
    :visible="isVisible"
    @update:visible="isVisible = $event"
></child-component>

// 子组件中触发更新
this.$emit('update:visible', false);

📘 Demo 0: 理解 @update:xxx（前置知识）

🎯 @update:xxx 到底是什么？
⚠️ 重要说明：

你可能在想："@update:xxx 是什么鬼？我之前没学过这个！"
别慌！这不是新概念，只是一种命名规范而已。

📚 回顾：你之前学过的自定义事件

在 [18_组件基础/4.组件通信-$emit子传父.html] 中，你学过：
// 子组件：触发自定义事件 this.$emit('my-event', '数据'); // 父组件：监听自定义事件 <child @my-event="handleEvent"></child> // 事件名可以随便起： @my-event ✅ 可以 @click-button ✅ 可以 @data-change ✅ 可以 @whatever ✅ 可以，任意名字都行！

🔍 @update:xxx 只是一种命名约定

// @update:xxx 本质上和普通自定义事件一模一样！ // 1. 普通自定义事件（你之前学的） this.$emit('my-event', '数据'); <child @my-event="handleEvent"></child> // 2. @update:xxx 自定义事件（只是名字特殊） this.$emit('update:visible', false); <child @update:visible="visible = $event"></child> // 看出来了吗？只是事件名不同而已！ // 'my-event' 是普通名字 // 'update:visible' 只是带了冒号的名字，仅此而已！

❓ 为什么要用 @update:xxx 这个命名？

对比项 随便起名 使用 update:xxx
子组件触发 $emit('close-dialog', false) $emit('update:visible', false)
父组件监听 @close-dialog="visible = $event" @update:visible="visible = $event"
能否用 .sync ❌ 不能，名字不符合规范 ✅ 可以简写为 :visible.sync
语义清晰度 ⚠️ 看不出要更新哪个 prop ✅ 一眼看出：更新 visible 属性
✅ 总结：

@update:xxx 就是普通的自定义事件，只不过：
1️⃣ 名字遵循 update:propName 的格式
2️⃣ 专门用于告诉父组件："我要更新某个 prop"
3️⃣ 这样就可以使用 .sync 语法糖简化代码
4️⃣ 如果不遵循这个命名，就不能用 .sync

💻 完整对比示例：

❌ 不遵循 update:xxx 命名

// 子组件 this.$emit('close', false); // 父组件（不能用 .sync） <Dialog :visible="show" @close="show = $event" /> // ❌ 不能这样写： <Dialog :visible.sync="show" /> // Vue 不知道监听哪个事件

✅ 遵循 update:xxx 命名

// 子组件 this.$emit('update:visible', false); // 父组件（可以用 .sync） <Dialog :visible="show" @update:visible="show = $event" /> // ✅ 可以简写为： <Dialog :visible.sync="show" /> // Vue 知道监听 update:visible

🔴 关键理解：

@update:xxx 不是一个新的Vue特性！
它只是自定义事件的一种命名规范，专门配合 .sync 使用。

如果你不用 .sync，完全可以用任意事件名！

下面是完全相同功能的计数器，用三种方式实现。

方式1️⃣: props + emit

父组件计数: {{ count1 }}

方式2️⃣: .sync 修饰符

父组件计数: {{ count2 }}

✅ 语法糖（简化了事件监听）

方式3️⃣: v-model

父组件计数: {{ count3 }}

✅ 专门用于单个值的双向绑定

📊 父组件代码对比：

// 方式1️⃣: props + emit <counter-props-emit :count="count1" @increment="count1 = $event" /> // ⚠️ 需要手动写事件监听
// 方式2️⃣: .sync <counter-sync :count.sync="count2" /> // ✅ .sync 自动监听 // update:count 事件
// 方式3️⃣: v-model <counter-vmodel v-model="count3" /> // ✅ v-model 自动监听 // input 事件

📊 子组件代码对比：

// 方式1️⃣: 普通 emit props: { count: Number }, methods: { increment() { // 事件名随便起 this.$emit( 'increment', this.count + 1 ); } }
// 方式2️⃣: .sync 要求 props: { count: Number }, methods: { increment() { // 必须叫 update:xxx this.$emit( 'update:count', this.count + 1 ); } }
// 方式3️⃣: v-model 要求 props: { value: Number ← 必须叫value }, methods: { increment() { // 必须叫 input this.$emit( 'input', this.value + 1 ); } }

✅ 三者关系总结：

对比项 props + emit .sync v-model
本质 最原始的方式 props + emit 的语法糖 props + emit 的语法糖
prop 名 任意 任意 必须是 value
事件名 任意 必须是 update:xxx 必须是 input
数量 无限制 可多个 只能一个
代码量 ❌ 多（要写监听） ✅ 少（自动监听） ✅ 少（自动监听）
使用场景 所有场景 多属性双向绑定 表单输入
🔴 关键理解：

1. .sync 和 v-model 都是 props + emit 的语法糖
它们只是自动帮你写了 @xxx="data = $event" 而已！

2. 区别只是约定不同：
• .sync：事件必须叫 update:propName，prop 名任意
• v-model：prop 必须叫 value，事件必须叫 input

3. 选择建议：
• 表单输入框 → 用 v-model
• 对话框、面板状态 → 用 .sync
• 多个属性需要同步 → 用 .sync（v-model 只能一个）

🔄 数据流对比详解：

📊 以 count = 5 为例，点击按钮后变成 6 的完整过程：

方式1️⃣: props + emit

父组件写法：
<counter :count="count1"
  @increment="count1 = $event">
⬇️ 1. 父传子：count1(5) → count
⬇️ 2. 用户点击
⬇️ 3. 子组件：$emit('increment', 6)
⬇️ 4. 父监听：increment 事件
⬇️ 5. 父执行：count1 = $event (6)
⬇️ 6. 父数据：count1 → 6
⬇️ 7. 传回子：count → 6
⚠️ 需要手动写监听器

方式2️⃣: .sync 修饰符

父组件写法：
<counter :count.sync="count2">
Vue自动转换为：
<counter :count="count2"
  @update:count="count2=$event">
⬇️ 1. 父传子：count2(5) → count
⬇️ 2. 用户点击
⬇️ 3. 子组件：$emit('update:count', 6)
⬇️ 4. 父自动监听：update:count 事件
⬇️ 5. 父自动执行：count2 = $event (6)
⬇️ 6. 父数据：count2 → 6
⬇️ 7. 传回子：count → 6
✅ .sync 自动添加监听器！

方式3️⃣: v-model

父组件写法：
<counter v-model="count3">
Vue自动转换为：
<counter :value="count3"
  @input="count3=$event">
⬇️ 1. 父传子：count3(5) → value
⬇️ 2. 用户点击
⬇️ 3. 子组件：$emit('input', 6)
⬇️ 4. 父自动监听：input 事件
⬇️ 5. 父自动执行：count3 = $event (6)
⬇️ 6. 父数据：count3 → 6
⬇️ 7. 传回子：value → 6
✅ v-model 自动添加监听器！
💡 核心理解：

三者的数据流程完全一样，都是：
父传子 → 用户操作 → 子$emit → 父监听 → 父更新 → 传回子

唯一的区别：
• 方式1：所有代码都要手写 ⚠️
• 方式2：.sync 自动生成 @update:xxx="data=$event" ✅
• 方式3：v-model 自动生成 @input="data=$event" ✅

所以 .sync 和 v-model 就是"懒人模式"，帮你少写代码！

🔄 .sync 双向绑定原理图解：

❓ 常见疑问：数据到底绑定到子组件的哪里？

答：绑定到子组件的 prop（不是 data）！ 


// 示例：父组件使用 .sync
<child-component :count.sync="parentCount"></child-component>
                      ↑             ↑
                 子组件的prop    父组件的data

// ==================== Vue 自动展开 ====================

<child-component 
    :count="parentCount"                   ← 【1】props 传值（父→子）
    @update:count="parentCount = $event"   ← 【2】事件监听（子→父）
></child-component>

// ==================== 数据绑定关系 ====================

父组件：
data() {
    return {
        parentCount: 5  ← 父组件的 data
    }
}

子组件：
Vue.component('child-component', {
    props: {
        count: Number   ← 子组件的 prop（接收父组件传来的值）
    },
    methods: {
        increment() {
            // 注意：不能直接修改 prop！
            // this.count = 6;  ❌ 错误！Vue 会警告
            
            // 正确做法：通过 emit 通知父组件
            this.$emit('update:count', this.count + 1);  ✅
        }
    }
});

// ==================== 双向绑定循环 ====================

初始状态：
    父组件 parentCount = 5
    │
    ├─【1】:count="parentCount"  （props 传值）
    │
    └──→ 子组件 count prop = 5

用户点击按钮：
    子组件执行 this.$emit('update:count', 6)
    │
    ├─【2】@update:count="parentCount=$event"  （事件监听）
    │
    └──→ 父组件 parentCount = 6

响应式更新：
    父组件 parentCount 变化（6）
    │
    ├─【3】因为有 :count="parentCount"，Vue 自动重新传值
    │
    └──→ 子组件 count prop 更新为 6

✅ 完成双向同步！
🔴 重要提醒：子组件不能直接修改 prop！

❌ 错误做法：
this.count = 6; // 直接修改 prop，Vue 会报错！

✅ 正确做法：
this.$emit('update:count', 6); // 通知父组件，让父组件修改

为什么要这样？
• Props 是单向数据流：父→子
• 子组件不应该直接修改父组件传来的数据
• 通过 $emit 通知父组件修改，保持数据流清晰
• 父组件修改后，会自动通过 prop 传回子组件

💡 一句话总结 .sync 的双向绑定：

父组件的 data ⇄ 子组件的 prop

• 父→子：通过 :count="parentCount" (props)
• 子→父：通过 $emit('update:count', value) (事件)
• 父组件更新后，自动传回子组件（响应式）

.sync 只是帮你自动写了 @update:count="parentCount=$event" 这一行！

3. 语义清晰

4. 代码简洁
不用写 @update:visible="visible = $event" 这么长

  • 常见应用：对话框、抽屉、折叠面板等组件状态

⚠️ 注意事项

  • 不能和表达式一起使用：:title.sync="doc.title + '!'" ❌
  • 不能用在字面量对象上：v-bind.sync="{ title: doc.title }" ❌
  • .sync 会破坏单向数据流，要谨慎使用
  • 建议只在明确需要双向绑定的场景使用

💡 最佳实践

  • ✅ 对话框、抽屉组件的 visible 状态
  • ✅ 折叠面板的展开/收起状态
  • ✅ 分页组件的当前页码、每页条数
  • ❌ 不建议用于复杂的业务逻辑数据
  • ❌ 不建议过度使用，会导致数据流混乱
