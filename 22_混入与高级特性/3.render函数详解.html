⚙️ Vue render 函数详解

掌握 Vue 底层渲染机制 - 创建虚拟 DOM

💡 什么是 render 函数？

render 函数是 Vue 虚拟 DOM 渲染的核心。当你编写模板时，Vue 内部会将模板编译成 render 函数。

🎯 为什么需要 render 函数？

  • ✅ 更强大：完整的 JavaScript 编程能力
  • ✅ 更灵活：动态生成复杂组件结构
  • ✅ 性能优化：避免模板编译，直接创建 VNode
  • ✅ 类型支持：TypeScript 更友好

📦 render 函数的基本结构

render: function(createElement) {
    // createElement(标签名, 数据对象, 子节点数组)
    return createElement('div', {
        attrs: { id: 'app' },
        class: { active: true },
        style: { color: 'red' }
    }, [
        createElement('h1', 'Hello World'),
        createElement('p', 'This is a paragraph')
    ]);
}

// ES6 简写 (h 是 hyperscript 的缩写)
render(h) {
    return h('div', [
        h('h1', 'Hello World'),
        h('p', 'This is a paragraph')
    ]);
}

📘 Demo 2: createElement 参数详解

🎯 h (createElement) 函数的三个参数
h 函数签名： createElement(标签名/组件, 数据对象, 子节点)
参数 类型 说明 示例
标签名 String | Object | Function HTML 标签名、组件对象或异步组件 'div', MyComponent
数据对象 Object 包含模板属性的对象（可选） { class, style, attrs, on... }
子节点 String | Array 文本内容或子 VNode 数组 '文本', [h('p', 'child')]

数据对象详细属性：

{ // 与 `v-bind:class` 相同 'class': { active: true }, // 与 `v-bind:style` 相同 style: { color: 'red', fontSize: '14px' }, // 普通 HTML 属性 attrs: { id: 'foo', type: 'text' }, // 组件 props props: { myProp: 'value' }, // DOM 属性 domProps: { innerHTML: '<b>HTML</b>' }, // 事件监听器（在 `on` 下） on: { click: this.handleClick }, // 仅用于组件的原生事件 nativeOn: { click: this.nativeClick }, // 自定义指令 directives: [ { name: 'my-directive', value: '2' } ], // 插槽（{ name: props => VNode | Array<VNode> }） scopedSlots: { default: props => h('span', props.text) }, // 其他特殊属性 key: 'myKey', ref: 'myRef' }

📘 Demo 3: 动态渲染组件

🎯 根据数据动态生成标题级别
// 动态标题组件 - 模板方式很难实现 Vue.component('dynamic-heading', { props: { level: { type: Number, required: true }, text: { type: String, required: true } }, render(h) { // 根据 level 动态生成 h1-h6 return h( 'h' + this.level, // 'h1', 'h2', 'h3'... { style: { color: '#764ba2', margin: '10px 0' } }, this.text ); } }); // 使用 <dynamic-heading :level="1" :text="'一级标题'"></dynamic-heading> <dynamic-heading :level="2" :text="'二级标题'"></dynamic-heading>
⚠️ 为什么用 render？
在模板中需要写很多 v-if/v-else来判断，而 render 函数只需一行代码。

📘 Demo 6: 函数式组件（Functional Component）

🎯 无状态、无实例的高性能组件
什么是函数式组件？
  • 没有响应式数据（no data）
  • 没有实例（no this）
  • 没有生命周期
  • 只接收 props，返回 VNode
  • 性能更好（渲染开销低）
// 函数式组件定义 Vue.component('list-item', { functional: true, // 标记为函数式组件 props: { item: { type: Object, required: true } }, // context 包含：props, children, slots, scopedSlots, data, parent, listeners, injections render(h, context) { const { name, version, color } = context.props.item; return h('div', { style: { padding: '15px', margin: '10px 0', border: `2px solid ${color}`, borderRadius: '8px' } }, [ h('strong', { style: { color } }, name), h('span', { style: { marginLeft: '10px', color: '#6c757d' } }, version) ]); } });
✅ 使用场景：展示型组件、列表项、纯UI组件

📘 Demo 7: 真实项目中 render 的使用情况

🎯 实际开发中如何使用 render
⚠️ 重要说明：

在真实项目中，99% 的组件都用 template，不用 render！
大部分开发者只在一个地方见过 render：main.js 的根组件挂载

📊 真实项目中的 render 使用频率：

场景 使用方式 频率
main.js 根组件 render: h => h(App) ⭐⭐⭐⭐⭐
普通业务组件 <template> 标签 ⭐⭐⭐⭐⭐
表格自定义列 传入 render 函数 ⭐⭐⭐
组件库开发 复杂动态组件 ⭐⭐
整个组件用 render 完全不用 template ⭐

💼 场景 1️⃣：main.js 根组件（最常见）

// src/main.js - 每个 Vue 项目都有这一行 import Vue from 'vue' import App from './App.vue' import router from './router' import store from './store' // 这是你唯一会写的 render 函数！ new Vue({ router, store, render: h => h(App) // ← 就这一行！ }).$mount('#app'); // 为什么这里用 render 而不是 template？ // 因为运行时版本的 Vue 不包含模板编译器，体积更小 // App.vue 会被 vue-loader 预编译成 render 函数

💼 场景 2️⃣：表格自定义列（Element UI）

// 你在 VueAdmin 项目中可能见过这种写法 <el-table :data="tableData"> <!-- 普通列：用模板 --> <el-table-column prop="name" label="姓名"></el-table-column> <!-- 自定义列：传入 render 函数 --> <el-table-column label="操作" :render="renderAction"></el-table-column> </el-table> export default { methods: { renderAction(h, { row }) { return h('div', [ h('el-button', { props: { type: 'primary', size: 'small' }, on: { click: () => this.handleEdit(row) } }, '编辑'), h('el-button', { props: { type: 'danger', size: 'small' }, on: { click: () => this.handleDelete(row) } }, '删除') ]); } } } // 但其实用插槽更常见： <el-table-column label="操作"> <template slot-scope="{ row }"> <el-button @click="handleEdit(row)">编辑</el-button> <el-button @click="handleDelete(row)">删除</el-button> </template> </el-table-column>

💼 场景 3️⃣：组件库开发（少数人）

// Element UI 的 MessageBox 组件内部使用 render // packages/message-box/src/main.vue export default { render(h) { return h('transition', { attrs: { name: 'msgbox-fade' } }, [ h('div', { directives: [{ name: 'show', value: this.visible }], class: 'el-message-box__wrapper' }, [ // ... 复杂的 VNode 结构 ]) ]); } }; // 但 99% 的开发者不需要开发组件库！

🎯 你在真实项目中会遇到的情况：

组件类型 使用方式
Header.vue <template> ✅
Sidebar.vue <template> ✅
UserList.vue <template> ✅
Login.vue <template> ✅
Dialog.vue <template> ✅
main.js render: h => h(App) ⚠️ 唯一的 render

✅ 真实开发建议：

  • 99% 的场景：用 <template> 写组件
  • 表格自定义列：优先用作用域插槽，而不是 render
  • 动态内容：用 v-if、v-for、计算属性即可
  • 只在 main.js：写一次 render: h => h(App)

⚠️ 何时才真正需要 render？

  • ❌ 不需要：普通业务组件（全用 template）
  • ❌ 不需要：表单、列表、详情页（全用 template）
  • ❌ 不需要：大部分自定义组件（template 够用）
  • ✅ 需要：开发类似 Element UI 的组件库（极少数人）
  • ✅ 需要：非常复杂的动态结构（几乎遇不到）

📚 知识点总结

💡 核心理解：render 在实际项目中很少用

真实情况：99% 的 Vue 项目组件都用 <template>！
• main.js：唯一会写的 render: h => h(App)
• 业务组件：全用 <template>
• 组件库开发：极少数场景才用 render

✅ render 函数 vs 模板

特性 模板（Template） render 函数
实际使用 ✅ 99% 的场景 ❌ 1% 的场景
易用性 ✅ 简单直观，类 HTML ❌ 需要理解 VNode
灵活性 ❌ 受模板语法限制 ✅ 完整 JavaScript 能力
性能 ✅ Vue 编译器优化 ✅ 直接创建 VNode（但优化少）
可维护性 ✅ 结构清晰易读 ❌ 代码嵌套复杂

💡 何时使用 render 函数？（真实答案）

  • ✅ main.js：render: h => h(App)（必写）
  • ⚠️ Element UI 表格：自定义列渲染（但插槽更好）
  • ⚠️ 开发组件库：复杂动态组件（极少数人）
  • ❌ 普通业务组件：完全不需要！

🎓 学习 render 的真正价值

虽然实际很少手写 render，但学习 render 能帮你：
✅ 理解 Vue 原理：template 如何转换为 VNode
✅ 理解虚拟 DOM：diff 算法的工作对象
✅ 阅读源码：Vue 内部全是 render 函数
✅ 调试问题：知道模板编译后的样子
✅ 面试加分：能说清楚 Vue 渲染原理

🔴 实际项目建议

不要为了用 render 而用 render！
• 能用 <template> 解决的，就用 template
• 需要动态内容，用 v-if/v-for/computed
• 只在确实无法用模板实现时，才考虑 render
• 大部分开发者整个职业生涯都不会手写完整 render
