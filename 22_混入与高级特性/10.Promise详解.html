① 为什么需要 Promise——先理解"回调地狱"

JavaScript 中很多操作是异步的（网络请求、定时器、文件读取……），早期只能用回调函数来处理结果。当操作步骤增多，回调就开始嵌套，形成"回调地狱"：

❌ 回调地狱：难以阅读和维护
login(user, function(err, token) {
  if (err) return cb(err)
  getProfile(token, function(err, profile) {
    if (err) return cb(err)
    getOrders(profile.id, function(err, orders) {
      if (err) return cb(err)
      // 每一层都要处理错误
      // 金字塔越来越深...
    })
  })
})
✅ Promise 链：扁平清晰
login(user)
  .then(token => getProfile(token))
  .then(profile => getOrders(profile.id))
  .then(orders => {
    // 处理订单
  })
  .catch(err => {
    // 所有错误统一在这里处理
  })
Promise 的本质：它是一个对象，代表"一个将来会有结果的操作"。你可以在操作完成前就把这个对象传递出去，等操作完成后再通过 .then() / .catch() 获取结果或错误。
② Promise 的三种状态——状态机

每个 Promise 对象都有且只有三种状态，一旦从 pending 变为另一种，就永远不会再变：

pending
等待中
→
resolve(value)
fulfilled
已成功
  
pending
等待中
→
reject(reason)
rejected
已失败
状态含义触发方式对应 .then/.catch
pending（等待中） 异步操作还在进行，结果未知 new Promise() 刚创建时 都不触发
fulfilled（已成功） 操作成功完成，有返回值 调用 resolve(value) 触发 .then(value => ...)
rejected（已失败） 操作失败，有错误原因 调用 reject(reason) 或抛出异常 触发 .catch(reason => ...) 
const p = new Promise((resolve, reject) => {
  // 刚创建：pending 状态
  setTimeout(() => {
    resolve('成功数据')   // → fulfilled，只会执行一次
    resolve('再次成功')   // 无效！状态已确定，第二次 resolve 被忽略
    reject('失败原因')    // 无效！已经 fulfilled，不会变成 rejected
  }, 1000)
})

console.log(p)  // Promise { <pending> }（1秒内打印）
// 1秒后 p 变为 → Promise { '成功数据' }
状态不可逆：Promise 一旦 resolve 或 reject，状态就固定了。这保证了回调只会被调用一次，不会出现"既成功又失败"的乱象。
③ 创建 Promise——executor 函数

用 new Promise(executor) 创建，executor 是一个立即执行的函数，接收 resolve 和 reject 两个函数：

const p = new Promise(/* executor */ (resolve, reject) => {
  // executor 在 new Promise() 时立即同步执行
  const rand = Math.random()
  if (rand > 0.5) {
    resolve({ code: 200, data: '请求成功' })   // 成功，传递结果
  } else {
    reject(new Error('网络错误'))              // 失败，传递错误
  }
})

三个快捷静态方法：直接创建已定状态的 Promise

// 直接创建一个 fulfilled 的 Promise
const p1 = Promise.resolve('立刻成功')
// 等价于 new Promise(resolve => resolve('立刻成功'))

// 直接创建一个 rejected 的 Promise
const p2 = Promise.reject(new Error('立刻失败'))
// 等价于 new Promise((_, reject) => reject(new Error('立刻失败')))
什么时候自己 new Promise？
通常你不需要手动创建 Promise——axios、fetch 等库已经帮你返回了 Promise，直接 .then() 或 await 就好。
只有在包装老式回调 API（如 setTimeout、XMLHttpRequest）时，才需要 new Promise。 
// 典型场景：把 setTimeout 包装成 Promise（sleep 函数）
function sleep(ms) {
  return new Promise(resolve => setTimeout(resolve, ms))
}

// 使用
sleep(1000).then(() => console.log('1秒后执行'))
// 或者
await sleep(1000)
console.log('1秒后执行')
④ .then() / .catch() / .finally()——消费 Promise

.then(onFulfilled, onRejected)——注册成功/失败回调

const p = fetchUser()  // 返回 Promise

// 写法1：.then() 传两个回调（不推荐，通常用 .catch 代替第二个参数）
p.then(
  user  => console.log('成功：', user),   // fulfilled 时执行
  error => console.log('失败：', error)   // rejected 时执行（不推荐）
)

// 写法2：.then() + .catch()（推荐）
p.then(user  => console.log('成功：', user))
 .catch(error => console.log('失败：', error))

.catch(onRejected)——只处理错误

// .catch 是 .then(undefined, onRejected) 的简写
// 优势：可以捕获 .then 链中任意位置抛出的错误（见后面的链式调用）
fetchUser()
  .then(user => user.id)
  .then(id  => fetchOrders(id))
  .catch(err => console.error('任意一步失败都来这里：', err))

.finally(onFinally)——无论成败都执行

fetchUser()
  .then(user  => { this.user = user })
  .catch(err  => { this.$message.error('加载失败') })
  .finally(() => {
    this.loading = false   // 无论成功失败，loading 都要关掉
  })

// 注意：.finally 的回调不接收任何参数，也不影响链上的值传递
回调什么时候执行？
Promise 的 .then/.catch 回调是微任务（microtask），会在当前同步代码全部执行完之后、下一个宏任务之前执行。这就是为什么 Promise 比 setTimeout 更"快"（即使 setTimeout 延迟是 0ms）。 
console.log('1')
Promise.resolve().then(() => console.log('2 Promise 微任务'))
setTimeout(() => console.log('3 setTimeout 宏任务'), 0)
console.log('4')

// 输出顺序：1 → 4 → 2 → 3
// Promise 微任务比 setTimeout(0) 早执行！
⑤ 链式调用——.then() 返回新 Promise

这是 Promise 最核心、最容易误解的特性：每次 .then() 都返回一个新的 Promise，让链式调用成为可能。

.then() 返回值规则

.then 回调的返回值下一个 .then 收到的值
返回一个普通值（数字、对象等） 该值本身，新 Promise 立即 fulfilled
返回一个 Promise 等这个 Promise 完成，用它的结果继续
抛出异常 throw 跳过后续 .then，直接进入最近的 .catch
没有返回值（return undefined） undefined，新 Promise fulfilled 
fetchUser()                           // 返回 Promise<User>
  .then(user => {
    console.log('用户：', user.name)
    return user.id                      // 返回普通值 → 下一个 .then 收到 id
  })
  .then(id => {
    console.log('ID：', id)
    return fetchOrders(id)             // 返回 Promise → 等它完成
  })
  .then(orders => {
    console.log('订单：', orders)       // 拿到 fetchOrders 的结果
    // 不返回任何值，下一个 .then 收到 undefined
  })
  .then(() => {
    console.log('全部完成')
  })

常见错误：忘记 return，导致链断了

// ❌ 忘记 return —— 第二个 .then 立即执行，拿不到 fetchOrders 的结果
fetchUser()
  .then(user => {
    fetchOrders(user.id)   // ❌ 没有 return！这个 Promise 被"丢弃"
  })
  .then(orders => {
    console.log(orders)    // undefined！不是订单数据
  })

// ✅ 必须 return
fetchUser()
  .then(user => return fetchOrders(user.id))  // 或者箭头函数省略 return
  .then(user => fetchOrders(user.id))           // 箭头函数单行，隐式 return
  .then(orders => console.log(orders))
链式调用最常见的 bug： 在 .then() 里调用了另一个返回 Promise 的函数，但忘记 return，导致链断开，后续 .then() 拿到的是 undefined。
⑥ 错误传播机制——.catch 能捕获整条链上的错误

.catch() 会捕获它之前整条链上任意位置的错误，包括：Promise reject、.then 中 throw、.then 中的同步错误。

fetchUser()
  .then(user => {
    if (!user.active) throw new Error('账户已禁用')  // ← throw 在这里
    return fetchOrders(user.id)
  })
  .then(orders => {
    // 上面 throw 了，这里被跳过
    console.log(orders)
  })
  .catch(err => {
    // ← 统一在这里处理：fetchUser 失败、throw、fetchOrders 失败 都来这
    console.error(err.message)
  })

在链中间恢复错误

fetchUser()
  .catch(err => {
    console.warn('获取用户失败，使用默认用户')
    return { id: 0, name: '游客' }  // 返回默认值，链继续正常执行
  })
  .then(user => fetchOrders(user.id))  // 用默认用户继续执行
  .then(orders => console.log(orders))
  .catch(err => console.error('订单加载失败：', err))
未处理的 Promise rejection（会让控制台报红）：
如果一个 Promise 被 reject 了，但没有任何 .catch() 处理它，浏览器会触发 unhandledrejection 事件，控制台出现红色报错。

在 Vue 项目中，async methods 里没有 try/catch 的 Promise 错误也会这样——所以一定要记得处理错误！
⑦ 静态方法——处理多个 Promise
方法 行为 适合场景
Promise.all(arr) 全部成功才 resolve（返回结果数组）；任一失败立即 reject 多个独立请求，需要全部成功
Promise.allSettled(arr) 等所有 Promise 完成（无论成败），返回每个的状态和值 需要知道每个请求的具体结果
Promise.race(arr) 取第一个完成的（无论成败），其余的忽略 超时控制
Promise.any(arr) 取第一个成功的；全部失败才 reject 多个备用数据源，取最快成功的

Promise.all——最常用，并行请求

// 同时发出多个请求，等全部完成
const [banners, products, user] = await Promise.all([
  axios.get('/api/banners'),
  axios.get('/api/products'),
  axios.get('/api/me')
])
// 三个请求同时发出，等最慢的那个完成
// 注意：其中任何一个 reject，整个 Promise.all 就立即 reject

Promise.allSettled——关心每一个结果

const results = await Promise.allSettled([
  axios.get('/api/a'),
  axios.get('/api/b'),  // 假设这个失败
  axios.get('/api/c')
])

results.forEach(result => {
  if (result.status === 'fulfilled') {
    console.log('成功：', result.value)   // { status: 'fulfilled', value: ... }
  } else {
    console.log('失败：', result.reason)  // { status: 'rejected', reason: ... }
  }
})

Promise.race——超时控制

// 经典用法：给请求添加超时限制
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error(`超时（${ms}ms）`)), ms)
  )
  return Promise.race([promise, timeout])
}

// 5秒内没响应就 reject
const res = await withTimeout(axios.get('/api/slow'), 5000)
⑧ 与 async/await 的关系——语法糖，底层是同一回事
async/await 是 Promise 的语法糖。任何能用 async/await 写的代码，都能用 Promise 链写出来，反之亦然。两者可以混用。

下面是完全等价的两种写法：

Promise 链写法
function loadUserOrders() {
  return fetchUser()
    .then(user => fetchOrders(user.id))
    .then(orders => {
      this.orders = orders
    })
    .catch(err => {
      this.$message.error(err.message)
    })
    .finally(() => {
      this.loading = false
    })
}
async/await 写法
async function loadUserOrders() {
  try {
    const user   = await fetchUser()
    const orders = await fetchOrders(user.id)
    this.orders  = orders
  } catch (err) {
    this.$message.error(err.message)
  } finally {
    this.loading = false
  }
}

混用——在 async/await 中使用 Promise 静态方法

// 实际项目中最常见的混用：async/await + Promise.all
async mounted() {
  this.loading = true
  try {
    // await + Promise.all = 并行 + 同步写法，两全其美
    const [banners, products] = await Promise.all([
      axios.get('/api/banners'),
      axios.get('/api/products')
    ])
    this.banners  = banners.data
    this.products = products.data
  } catch (err) {
    this.$message.error('加载失败')
  } finally {
    this.loading = false
  }
}

什么时候用 .then 链，什么时候用 async/await？

场景推荐理由
Vue methods、生命周期钩子 async/await 可读性更好，try/catch 处理错误更直观
工具函数返回 Promise 供调用方处理 .then 链 函数本身不处理错误，交给调用方
并行多个请求 两者混用（await + Promise.all） 最简洁
简单的一次性转换 .then 代码量更少：fetch(url).then(r => r.json())

📝 一页纸总结
概念一句话
Promise 是什么代表"未来某时刻的一个值"的对象，有三个不可逆状态
resolve / reject让 Promise 从 pending 变为 fulfilled / rejected
.then()注册成功回调，返回新 Promise，用于链式调用
.catch()捕获整条链上的错误，等价于 .then(undefined, fn)
.finally()无论成败都执行，不接收参数，不影响链上的值
链式每步必须 return不 return，下一个 .then 收到 undefined，链就断了
Promise.all全部成功才继续，一个失败即失败，用于并行请求
Promise.allSettled等所有结果（不管成败），用于需要知道每个状态时
Promise.race取第一个完成的，用于超时控制
async/await 关系它是 Promise 的语法糖，底层完全一样，可以混用
