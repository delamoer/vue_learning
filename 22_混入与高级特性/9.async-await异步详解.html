① 什么是"异步"——从直觉开始理解

JavaScript 是单线程的，一次只能做一件事。但很多操作需要"等待"——等网络返回数据、等计时器到时、等文件读取完成……

如果等待期间什么都不做，页面就会"卡死"。所以 JS 用异步来解决：把"要等的事"丢出去，先继续执行后面的代码，等结果回来了再处理。

最简单的比喻：
你在奶茶店点单（发起请求），店员说"好了叫你"（异步），你不需要站在那里发呆，可以先去旁边坐着刷手机（继续执行后面的代码）。奶茶做好了，店员叫你（回调/resolve），你去取奶茶（处理结果）。

同步 vs 异步 的代码表现

// 同步：从上到下，一行执行完才执行下一行
console.log('第1步')
console.log('第2步')
console.log('第3步')
// 输出顺序：第1步 → 第2步 → 第3步

// 异步：setTimeout 把回调"延迟"执行
console.log('第1步')
setTimeout(() => {
  console.log('第2步（1秒后）')
}, 1000)
console.log('第3步')
// 输出顺序：第1步 → 第3步 → 第2步（1秒后）
// 注意：第3步没有等第2步！
常见异步场景： 网络请求（axios/fetch）、setTimeout / setInterval、读取文件（Node）、用户事件（点击按钮）、Promise、动画回调
② 回调地狱 → Promise → async/await 的演进

异步操作早期用回调函数处理，但当异步操作嵌套时，代码会变成"回调地狱"，难以阅读和维护：

// ❌ 回调地狱：先登录，再获取用户信息，再获取订单列表
login(user, function(err, token) {
  if (err) { return handleError(err) }
  getUserInfo(token, function(err, info) {
    if (err) { return handleError(err) }
    getOrderList(info.id, function(err, orders) {
      if (err) { return handleError(err) }
      // 到这里才能用 orders……已经嵌套了3层
      console.log(orders)
    })
  })
})

Promise 改善了链式调用

// ✅ Promise 链式：更清晰，但还是有点啰嗦
login(user)
  .then(token => getUserInfo(token))
  .then(info  => getOrderList(info.id))
  .then(orders => console.log(orders))
  .catch(err  => handleError(err))

async/await 让异步代码"看起来像同步"

// ✅✅ async/await：最清晰，最直观，本质还是 Promise
async function loadOrders() {
  const token  = await login(user)
  const info   = await getUserInfo(token)
  const orders = await getOrderList(info.id)
  console.log(orders)
}
// 读起来和同步代码一样，但实际上每一行都在"等待"异步结果
结论：async/await 不是新功能，是 Promise 的语法糖。
它们底层完全一样，只是写法更优雅。你在项目里看到 await xxx()，就意味着 xxx() 返回的是一个 Promise。

Promise 是什么？三种状态

状态含义触发
pending（等待中）还在执行，结果未知Promise 刚创建时
fulfilled（已成功）操作成功，有返回值调用 resolve(value)
rejected（已失败）操作失败，有错误信息调用 reject(error)
// 手动创建 Promise 的结构（了解即可，通常不需要自己写）
const p = new Promise((resolve, reject) => {
  // 执行异步操作...
  if (成功) {
    resolve(结果数据)   // → fulfilled，await 拿到这个值
  } else {
    reject(new Error('失败原因'))  // → rejected，await 抛出异常
  }
})
③ async / await 语法详解

规则一：await 必须在 async 函数内使用

// ❌ 错误：在普通函数里用 await
function bad() {
  const data = await fetchData()  // SyntaxError！
}

// ✅ 正确：函数声明前加 async
async function good() {
  const data = await fetchData()  // ✅
}

// ✅ 箭头函数同样可以
const good2 = async () => {
  const data = await fetchData()
}

规则二：async 函数总是返回 Promise

async function getNum() {
  return 42
}

// 调用 async 函数，得到的是 Promise，不是 42
console.log(getNum())    // Promise { 42 }

// 要拿到 42，必须 await 或 .then()
const n = await getNum()  // 42
getNum().then(n => console.log(n))  // 42

规则三：await 暂停当前 async 函数，不阻塞整个线程

async function demo() {
  console.log('A')
  const result = await slowRequest()  // 暂停在这里等待，但其他代码可以运行
  console.log('B', result)
}

demo()
console.log('C')

// 输出：A → C → B（C 不等 B，因为 B 在等异步结果）

规则四：await 可以用于任何返回 Promise 的表达式

// await axios 请求（最常见）
const res = await axios.get('/api/users')

// await setTimeout 包装成 Promise（延迟）
const sleep = ms => new Promise(r => setTimeout(r, ms))
await sleep(1000)  // 等 1 秒

// await 普通值（不是 Promise，直接返回）
const x = await 42  // x = 42（无意义但合法）

// await 多个并行请求：用 Promise.all
const [users, products] = await Promise.all([
  axios.get('/api/users'),
  axios.get('/api/products')
])
// 两个请求同时发出，都完成后才继续，比串行快很多
串行 vs 并行（重要！）

串行（一个等一个，慢）：
const a = await req1() // 等1秒
const b = await req2() // 再等1秒，共2秒

并行（同时发出，快）：
const [a, b] = await Promise.all([req1(), req2()]) // 共1秒

如果两个请求之间没有依赖关系，一定要用 Promise.all 并行！
④ 错误处理：try/catch 是标配

当 await 的 Promise 被 reject（失败），会抛出异常。必须用 try/catch 捕获，否则是未处理的错误。

// ❌ 没有错误处理：请求失败时，控制台报错，用户看到白屏
async function loadData() {
  const res = await axios.get('/api/users')  // 如果失败，崩了
  this.list = res.data
}

// ✅ 标准写法：try/catch 包裹
async function loadData() {
  try {
    const res = await axios.get('/api/users')
    this.list = res.data
  } catch (error) {
    console.error('加载失败：', error)
    this.$message.error('数据加载失败，请重试')
  }
}

在 Vue 中典型的完整写法（带 loading 状态）

async loadUsers() {
  this.loading = true   // 开始：显示 loading
  try {
    const res = await axios.get('/api/users')
    this.users = res.data
  } catch (err) {
    this.$message.error('请求失败')
  } finally {
    this.loading = false  // 无论成功失败，都关闭 loading
  }
}
finally 块的价值： 无论 try 成功还是 catch 捕获了异常，finally 都会执行。非常适合用来关闭 loading 状态，防止"请求失败后 loading 转圈转到天荒地老"。

另一种写法：不用 try/catch，用 .catch()

// 两种写法等价，选你喜欢的风格即可
async function loadData() {
  const res = await axios.get('/api/users').catch(err => {
    console.error(err)
    return null  // 失败时返回 null，避免后续代码崩溃
  })
  if (!res) return  // 请求失败，提前退出
  this.list = res.data
}
⑤ 最关键问题：什么时候用 async/await，什么时候不用？
判断标准只有一个：这个操作需要等待结果吗？
如果需要"等待某件事完成才能继续"——就需要 async/await（或 Promise）。
如果操作是瞬间完成的、不需要等待——就用普通函数。
场景 需要 async/await？ 原因
发送网络请求（axios/fetch） ✅ 必须 网络 I/O 是异步的，需要等待服务器响应
读写 localStorage ❌ 不需要 localStorage 是同步的，立即返回结果
计算总价、过滤列表 ❌ 不需要 纯 JS 计算，立即完成，用 computed 更合适
等待 Promise.all（多个并发请求） ✅ 必须 需要等所有 Promise 完成
setTimeout 延迟操作 ✅ 若需要等待 把 setTimeout 包成 Promise，再 await
修改 data 中的变量 ❌ 不需要 赋值是同步的
调用 Vuex action（内部有请求） ✅ 通常需要 action 本身返回 Promise，需要知道完成时机
v-on 事件处理器（如按钮点击） ✅ 内部有请求时 Vue 支持 async methods，放心用
生命周期钩子（created/mounted） ✅ 内部有请求时 直接在 created/mounted 前加 async 即可
watch 的 handler ✅ 内部有请求时 handler 可以是 async function

具体代码对比

// ── 不需要 async/await 的普通方法 ────────────────────

// ✅ 计算、格式化：纯同步，用普通函数
formatPrice(price) {
  return '¥' + price.toFixed(2)
},

// ✅ 操作 DOM、修改 data：同步，不需要 await
toggleMenu() {
  this.menuVisible = !this.menuVisible
},

// ✅ 过滤筛选：纯计算，用 computed 更好
computed: {
  filteredList() {
    return this.list.filter(item => item.name.includes(this.keyword))
  }
},


// ── 需要 async/await 的场景 ────────────────────

// ✅ 网络请求：必须 async
async loadList() {
  try {
    const res = await axios.get('/api/list')
    this.list = res.data
  } catch (e) {
    this.$message.error('加载失败')
  }
},

// ✅ 提交表单（需要知道成功/失败再跳转）
async handleSubmit() {
  const valid = await this.$refs.form.validate().catch(() => false)
  if (!valid) return
  try {
    await axios.post('/api/save', this.form)
    this.$message.success('保存成功')
    this.$router.push('/')   // 成功后才跳转
  } catch (e) {
    this.$message.error('保存失败')
  }
},

// ✅ mounted 中加载初始数据
async mounted() {
  await this.loadList()
  // 确保数据加载完才做后续操作
}
⑥ 在 Vue 2 中使用 async/await 的完整模式

模式一：生命周期钩子中请求初始数据

export default {
  data() {
    return { list: [], loading: false }
  },
  // created 比 mounted 早，适合不依赖 DOM 的数据请求
  async created() {
    this.loading = true
    try {
      const res = await axios.get('/api/list')
      this.list = res.data
    } finally {
      this.loading = false
    }
  }
}

模式二：watch 监听路由变化后重新请求

watch: {
  // 路由 id 变了就重新加载商品详情
  '$route.params.id': {
    immediate: true,
    async handler(id) {
      const res = await axios.get(`/api/product/${id}`)
      this.product = res.data
    }
  }
}

模式三：调用 Vuex action 并等待结果

methods: {
  async handleLogin() {
    try {
      // dispatch 返回 action 的 Promise，可以 await
      await this.$store.dispatch('user/login', this.form)
      this.$message.success('登录成功')
      this.$router.push('/')
    } catch (e) {
      this.$message.error(e.message)
    }
  }
}

模式四：并行请求，使用 Promise.all

methods: {
  async loadPageData() {
    this.loading = true
    try {
      // 两个请求同时发出，等最慢的那个完成，比串行快
      const [userRes, orderRes] = await Promise.all([
        axios.get('/api/me'),
        axios.get('/api/orders')
      ])
      this.user   = userRes.data
      this.orders = orderRes.data
    } finally {
      this.loading = false
    }
  }
}

模式五：依赖上一步结果的串行请求

methods: {
  async loadUserOrders() {
    // 必须先知道用户 id，才能查订单——只能串行
    const userRes = await axios.get('/api/me')
    const userId  = userRes.data.id

    const orderRes = await axios.get(`/api/orders?userId=${userId}`)
    this.orders = orderRes.data
  }
}
Vue 2 中 async methods 的注意事项：
Vue 本身对 async methods 有完整支持，但有一点要注意：async 方法返回的 Promise，Vue 不会自动捕获其中的异常并展示错误，异常会变成 unhandledRejection。所以你必须自己在 async 方法里写 try/catch！
⑦ 常见误区 & 陷阱

误区一：以为 await 会让代码"同步执行"

async function test() {
  console.log('1')
  const r = await fetchData()
  console.log('2', r)
}

test()
console.log('3')

// 输出：1 → 3 → 2
// ❌ 误区：以为是 1 → 2 → 3
// ✅ 正确：await 只暂停 test() 函数内部，不阻塞函数外面的 console.log('3')

误区二：在循环里串行发请求（性能问题）

// ❌ 慢！每次循环都等上一个请求完成
for (const id of ids) {
  const res = await axios.get(`/api/item/${id}`)
  results.push(res.data)
}

// ✅ 快！所有请求并行发出
const results = await Promise.all(
  ids.map(id => axios.get(`/api/item/${id}`))
)

误区三：忘记 await，以为拿到了数据

async mounted() {
  // ❌ 忘了写 await！res 是 Promise 对象，不是数据
  const res = axios.get('/api/list')
  this.list = res.data  // undefined！Promise 没有 .data

  // ✅ 正确
  const res = await axios.get('/api/list')
  this.list = res.data  // ✅ 正确的数组
}

误区四：在 forEach 里用 async/await（不生效！）

// ❌ 错误：forEach 的回调是 async，但 forEach 本身不 await
ids.forEach(async id => {
  const res = await axios.get(`/api/item/${id}`)
  console.log(res.data)   // 顺序不可预测，并且 forEach 结束时请求未必完成
})

// ✅ 正确：用 for...of 配合 await（串行）
for (const id of ids) {
  const res = await axios.get(`/api/item/${id}`)
  console.log(res.data)
}

// ✅ 正确：用 Promise.all + map（并行）
await Promise.all(ids.map(async id => {
  const res = await axios.get(`/api/item/${id}`)
  console.log(res.data)
}))

误区五：async/await 不能用在模板里

// ❌ 模板里不能直接 await，不合法
<template>
  <div>{{ await fetchName() }}</div>  <!-- 报错！ -->
</template>

// ✅ 正确：在 mounted/created 里获取数据，存到 data，模板展示 data
data() { return { name: '' } },
async created() {
  this.name = await fetchName()
}

📝 核心总结 — 一句话记忆法
问题答案
什么时候加 async？ 方法内部有 await 的时候（有 await 必须有 async）
什么时候用 await？ 调用返回 Promise 的函数，且需要等待结果（axios/fetch/dispatch 等）
普通方法什么时候用？ 纯计算、修改 data、操作 DOM——不涉及等待的操作
async/await 和 Promise 什么关系？ async/await 是 Promise 的语法糖，底层完全一样
错误怎么捕获？ 必须用 try/catch 包裹，finally 用来关闭 loading
多个独立请求怎么写最快？ await Promise.all([ req1(), req2() ]) 并行
🎯 实际项目中的经验法则：
只要是调用 axios（或任何 API 函数），方法就加 async，调用前加 await，外面包 try/catch。
其他情况（计算属性、事件的同步操作、修改变量）都用普通方法，不需要 async/await。
