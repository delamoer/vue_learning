🚌 Vue组件通信 - 事件总线EventBus

兄弟组件 & 任意组件之间的通信解决方案

📚 Demo 1: 什么是事件总线（Event Bus）

🎯 核心概念

  • 事件总线（Event Bus）：一个空的Vue实例，作为中央事件管理器
  • 作用：实现任意组件之间的通信（尤其是兄弟组件）
  • 原理：利用Vue实例的$on、$emit、$off方法
  • 适用场景：组件层级复杂，props和$emit不方便时

🏢 类比：公司内的广播系统

想象一个公司的广播系统：

1️⃣ 广播室（Event Bus）
- 就像公司的广播室，负责接收和发送消息
- 它本身是个空房间，只是个通信中介

2️⃣ 部门员工（各个组件）
- 销售部（组件A）可以通过广播发消息
- 技术部（组件B）可以监听广播接收消息
- 人事部（组件C）也可以监听和发送

3️⃣ 通信过程
- 销售部拿起话筒广播："下午3点开会"（$emit触发事件）
- 所有订阅了"会议通知"频道的部门都能听到（$on监听事件）
- 各部门不需要直接联系，通过广播室就能通信

💡 这就是Event Bus的本质：一个中央消息中间件！

// 1. 创建事件总线（在main.js或单独文件中） const EventBus = new Vue()
// 或者挂载到Vue原型上，方便全局访问 Vue.prototype.$bus = new Vue()
// 2. 组件A：发送消息（触发事件） EventBus.$emit('message', 'Hello from A')
// 3. 组件B：接收消息（监听事件） EventBus.$on('message', (data) => { console.log(data) // 'Hello from A' })
// 4. 组件销毁时：移除监听（避免内存泄漏） EventBus.$off('message')
通信方式 适用场景 优点 缺点
props 父→子 简单直观，类型验证 只能单向向下传递
$emit 子→父 明确的事件流向 只能向上传递一层
Event Bus 任意组件间 灵活，跨层级通信 难以追踪，容易混乱
Vuex 大型应用状态管理 集中管理，易于调试 学习成本高，小应用过重
💡 理解要点：
1. Event Bus本质是一个空的Vue实例，只利用它的事件系统
2. 组件通过$bus.$emit()发送事件，通过$bus.$on()监听事件
3. 特别适合兄弟组件通信，避免了"父→子→孙"的层层传递
4. 使用后要记得$off()移除监听，防止内存泄漏
5. 中小型项目推荐，大型项目建议使用Vuex

🎬 Demo 2: 基础使用 - 兄弟组件通信

场景：两个兄弟组件（ComponentA和ComponentB）之间互相发送消息
📋 事件日志：

暂无事件记录，点击按钮触发事件...
// 创建事件总线
const EventBus = new Vue()
// 组件A：发送消息
Vue.component('component-a', { template: ` <div class="component component-a"> <h3>组件 A</h3> <button @click="sendToB">发送消息给B</button> </div> `, methods: { sendToB() { // 触发事件，发送数据 EventBus.$emit('a-to-b', 'Hello from A!') } } })
// 组件B：接收消息
Vue.component('component-b', { data() { return { message: '等待接收消息...' } }, mounted() { // 监听事件，接收数据
EventBus.$on('a-to-b', (data) => { this.message = data }) }, beforeDestroy() { // 组件销毁前移除监听 EventBus.$off('a-to-b') } })

🎚️ Demo 5: $on、$once、$off 详解

学习：Event Bus的三个核心API的使用方法
API方法 语法 作用 使用场景
$on $bus.$on('event', callback) 监听事件，可触发多次 持续监听，如聊天消息
$once $bus.$once('event', callback) 监听事件，只触发一次后自动移除 一次性操作，如弹窗确认
$off $bus.$off('event', callback?) 移除事件监听 组件销毁时，防止内存泄漏
$emit $bus.$emit('event', ...args) 触发事件，传递数据 发送消息或通知
// 1. $on - 持续监听 EventBus.$on('message', (data) => { console.log(data) }) EventBus.$emit('message', '第1次') // 触发 EventBus.$emit('message', '第2次') // 触发 EventBus.$emit('message', '第3次') // 触发 // 2. $once - 只监听一次 EventBus.$once('init', (data) => { console.log(data) }) EventBus.$emit('init', '第1次') // 触发 EventBus.$emit('init', '第2次') // 不触发 // 3. $off - 移除监听 const handler = (data) => console.log(data) EventBus.$on('test', handler) EventBus.$off('test', handler) // 移除特定回调 EventBus.$off('test') // 移除该事件所有回调 EventBus.$off() // 移除所有事件监听（慎用！）

⚠️ 重要注意事项

1. 必须在beforeDestroy中$off：
   如果组件被销毁但没有移除监听，会造成内存泄漏！

2. $off移除监听的三种方式：
   • $off('event', callback) - 移除特定事件的特定回调
   • $off('event') - 移除特定事件的所有回调
   • $off() - 移除所有事件监听（慎用，会影响其他组件）

3. 回调函数不能用箭头函数：
   如果需要访问组件的this，不能用箭头函数，除非在外面用变量保存this

✅ Demo 6: 实战案例 - Todo分类管理

场景：三个分类面板（工作、学习、生活），点击完成按钮可将任务移到"已完成"面板
💡 技术要点：
1. 输入组件通过$emit('add-todo', {category, text})发送新任务
2. 各分类面板通过$on('add-todo')接收并添加任务
3. 点击完成按钮通过$emit('complete-todo', {category, text})通知
4. 已完成面板通过$on('complete-todo')接收并显示
5. 统计组件监听所有事件，实时更新数据

🌟 Demo 7: Event Bus 最佳实践

✅ 推荐做法

  • 统一管理事件名称：在单独的常量文件中定义事件名，避免拼写错误
  • 挂载到Vue原型：Vue.prototype.$bus = new Vue()，方便全局访问
  • 在mounted中监听：确保组件已挂载，避免监听失败
  • 在beforeDestroy中移除：必须$off移除监听，防止内存泄漏
  • 事件命名规范：使用kebab-case，如'user-login'、'data-update'
  • 传递数据封装：复杂数据用对象封装，便于扩展
  • 添加注释：在$emit和$on处添加注释，说明事件用途

❌ 避免的做法

❌ 滥用Event Bus：不是所有通信都要用，父子组件优先用props/$emit
❌ 忘记$off：组件销毁不移除监听会内存泄漏
❌ 事件命名混乱：没有规范，难以维护
❌ 过度使用$bus.$off()：移除所有监听会影响其他组件
❌ 大型项目使用：Event Bus适合中小项目，大型项目用Vuex

// ===== eventBus.js ===== import Vue from 'vue' // 创建事件总线 export const EventBus = new Vue() // 定义事件名称常量（避免拼写错误） export const EVENT_TYPES = { USER_LOGIN: 'user-login', USER_LOGOUT: 'user-logout', DATA_UPDATE: 'data-update', SHOW_TOAST: 'show-toast' } // ===== main.js ===== import { EventBus } from './eventBus' // 挂载到Vue原型，全局访问 Vue.prototype.$bus = EventBus // ===== ComponentA.vue ===== import { EVENT_TYPES } from '@/eventBus' export default { methods: { login() { // 使用常量，避免拼写错误 this.$bus.$emit(EVENT_TYPES.USER_LOGIN, { username: '张三', token: 'abc123' }) } } } // ===== ComponentB.vue ===== import { EVENT_TYPES } from '@/eventBus' export default { data() { return { userInfo: null } }, mounted() { // 监听登录事件 this.$bus.$on(EVENT_TYPES.USER_LOGIN, this.handleLogin) }, methods: { handleLogin(data) { this.userInfo = data } }, beforeDestroy() { // 必须移除监听！ this.$bus.$off(EVENT_TYPES.USER_LOGIN, this.handleLogin) } }

🎯 Event Bus vs Vuex 如何选择？

使用 Event Bus 的场景：
• 中小型项目（10-30个组件）
• 偶尔需要跨组件通信
• 不需要状态持久化
• 临时的、一次性的事件通知

使用 Vuex 的场景：
• 大型项目（30+组件）
• 多个组件共享状态
• 需要状态持久化（如登录信息）
• 需要时间旅行调试
• 复杂的状态变更逻辑

💡 记住：Event Bus是轻量级工具，Vuex是完整的状态管理方案！
