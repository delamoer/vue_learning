🎰 Vue组件插槽 - Slot

内容分发 | 组件的"占位符"机制

📚 Demo 1: 什么是插槽（Slot）？

🎯 核心概念

  • 插槽（Slot）：组件的内容分发口，允许父组件向子组件传递内容
  • 内容分发：父组件决定子组件显示什么内容
  • 组件复用：同一个组件，不同内容
  • 灵活性：结构固定，内容可变

🏢 类比：模板方法模式（Template Method Pattern）

Spring/Java 中的模板方法：

1️⃣ 抽象类定义"框架"
abstract class Report {
  void generate() {
    printHeader(); // 固定部分
    printBody(); // 子类实现（插槽！）
    printFooter(); // 固定部分
  }
  abstract void printBody(); // 抽象方法（插槽）
}

2️⃣ 子类"填充内容"
class SalesReport extends Report {
  void printBody() {
    // 填充销售数据（内容分发）
  }
}

💡 插槽就是这个原理：
- 子组件定义"框架"和"插槽位置"
- 父组件"填充内容"到插槽中
- 同一个组件，不同内容，不同效果！

🏠 类比：装修房子

想象你买了一个精装修的房子：

🏗️ 开发商提供（子组件）：
• 房子结构、墙壁、门窗 → 固定的HTML结构
• 预留了"客厅、卧室、书房"的位置 → <slot>

🎨 你自己装修（父组件）：
• 客厅放沙发、电视 → 插槽1的内容
• 卧室放床、衣柜 → 插槽2的内容
• 书房放书桌、书架 → 插槽3的内容

📋 同一套房结构，不同装修风格！
- 小明的家：现代简约风
- 小红的家：中式古典风
- 同一个"房子组件"，不同的"内容填充"！

// 子组件：定义"框架"和"插槽" Vue.component('my-button', { template: ` <button class="my-button"> <slot></slot> <-- 插槽！父组件可以在这里插入内容 </button> ` })
// 父组件：向插槽"填充内容" <my-button>点击我</my-button> // 显示：点击我 <my-button>提交表单</my-button> // 显示：提交表单 <my-button>❤️ 收藏</my-button> // 显示：❤️ 收藏 <my-button><i>删除</i></my-button> // 可以插入HTML！

🎬 Demo 2: 默认插槽 - 基础用法

场景：创建一个按钮组件，内容由父组件决定
// 1. 子组件：定义插槽 Vue.component('my-button', { template: ` <button class="my-button"> <slot>默认文字</slot> <-- 如果父组件没传内容，显示"默认文字" </button> ` })
// 2. 父组件：使用并填充内容 <my-button>点击我</my-button> // 替换默认内容 <my-button></my-button> // 没传内容，显示"默认文字" <my-button> <span style="color: red">删除</span> // 可以传HTML </my-button>

⚠️ 注意事项

1. 插槽内容的编译作用域：
   插槽内容是在父组件中编译的，只能访问父组件的数据

2. 后备内容（默认内容）：
   <slot>默认文字</slot> - 父组件不传内容时显示

3. 插槽可以包含任何内容：
   文本、HTML、甚至其他组件

🏷️ Demo 3: 具名插槽 - 多个插槽位置

场景：卡片组件有标题、内容、底部三个区域，需要分别填充
// 1. 子组件：定义多个具名插槽 Vue.component('my-card', { template: ` <div class="my-card"> <div class="card-header"> <slot name="header">默认标题</slot> <-- 具名插槽：header </div> <div class="card-body"> <slot>默认内容</slot> <-- 默认插槽（没有name） </div> <div class="card-footer"> <slot name="footer">默认底部</slot> <-- 具名插槽：footer </div> </div> ` })
// 2. 父组件：向具名插槽填充内容（Vue 2.6+ 新语法） <my-card> <template v-slot:header> <-- v-slot:header 或简写 #header <h2>这是标题</h2> </template> <!-- 默认插槽可以不用template --> <p>这是卡片内容</p> <template v-slot:footer> <button>确定</button> </template> </my-card>
// 3. 父组件：旧语法（Vue 2.6 之前） <my-card> <h2 slot="header">标题</h2> <-- slot属性 <p>内容</p> <button slot="footer">确定</button> </my-card>

🔄 Demo 4: 作用域插槽 - 子组件向父组件传数据

场景：列表组件提供数据，父组件自定义渲染方式

💡 理解作用域插槽

普通插槽 vs 作用域插槽：

普通插槽：父组件传内容给子组件（父→子）
• 父组件决定显示什么
• 只能访问父组件数据

作用域插槽：子组件传数据给父组件（子→父）
• 子组件提供数据
• 父组件决定如何渲染这些数据
• 数据的"反向传递"！

类比餐厅：
• 普通插槽 = 你点菜，厨房做好端上来
• 作用域插槽 = 厨房提供食材，你自己烹饪！

// 1. 子组件：提供数据给插槽 Vue.component('user-list', { data() { return { users: [ { id: 1, name: '张三', age: 25 }, { id: 2, name: '李四', age: 30 } ] } }, template: ` <div> <div v-for="user in users" :key="user.id"> <slot :user="user"> <-- 通过props传递数据 {{ user.name }} <-- 默认渲染 </slot> </div> </div> ` })
// 2. 父组件：接收数据并自定义渲染 <user-list> <template v-slot="slotProps"> <-- slotProps接收所有传递的数据 <strong>{{ slotProps.user.name }}</strong> - {{ slotProps.user.age }}岁 </template> </user-list>
// 3. 解构写法（推荐） <user-list> <template v-slot="{ user }"> <-- 解构赋值 <span style="color: blue">{{ user.name }}</span> </template> </user-list>

📝 Demo 5: 实战案例 - 对话框组件

场景：封装一个通用对话框，标题和内容可自定义
// 对话框组件：使用具名插槽 Vue.component('my-dialog', { props: ['visible'], template: ` <div v-if="visible" class="my-dialog-overlay"> <div class="my-dialog"> <div class="dialog-header"> <div class="dialog-title"> <slot name="title">提示</slot> </div> <button @click="$emit('close')" class="dialog-close">✕</button> </div> <div class="dialog-body"> <slot></slot> <-- 默认插槽：内容 </div> <div class="dialog-footer"> <slot name="footer"> <button @click="$emit('close')">关闭</button> </slot> </div> </div> </div> ` })

📊 Demo 6: 实战案例 - 表格组件（作用域插槽）

场景：表格组件提供数据，父组件自定义每列的渲染方式

💡 这就是 Element UI 表格的原理！

<el-table> 的实现原理：

1️⃣ 表格组件提供【行数据】（作用域插槽）
2️⃣ 父组件接收数据，自定义渲染（标签、按钮、图片）
3️⃣ 灵活性强：同一份数据，不同的展示方式！

对比：
• 不用插槽：表格组件写死渲染方式，不灵活❌
• 使用插槽：父组件自定义渲染，超级灵活✅

// 表格组件：通过作用域插槽传递行数据 Vue.component('my-table', { props: ['columns', 'data'], template: ` <table class="my-table"> <thead> <tr> <th v-for="col in columns" :key="col.prop"> {{ col.label }} </th> </tr> </thead> <tbody> <tr v-for="row in data" :key="row.id"> <td v-for="col in columns" :key="col.prop"> <slot :name="col.prop" :row="row"> <-- 传递行数据 {{ row[col.prop] }} <-- 默认显示 </slot> </td> </tr> </tbody> </table> ` })
// 父组件：自定义列渲染 <my-table :columns="columns" :data="users"> <!-- 自定义"状态"列 --> <template #status="{ row }"> <span :class="'status-' + row.status"> {{ row.status === 'active' ? '在线' : '离线' }} </span> </template> <!-- 自定义"操作"列 --> <template #actions="{ row }"> <button @click="edit(row)">编辑</button> <button @click="del(row)">删除</button> </template> </my-table>

⚡ Demo 7: 插槽简写语法（Vue 2.6+）

学习：v-slot 的各种简写方式
// ========== 1. 具名插槽简写 ==========
// 完整写法 <template v-slot:header>标题</template>
// 简写（# 代替 v-slot:） <template #header>标题</template>

// ========== 2. 默认插槽简写 ==========
// 完整写法 <my-component> <template v-slot:default>内容</template> </my-component>
// 简写1（省略default） <my-component> <template v-slot>内容</template> </my-component>
// 简写2（只有默认插槽时，可以直接写在组件标签上） <my-component v-slot="slotProps"> {{ slotProps.data }} </my-component>

// ========== 3. 作用域插槽简写 ==========
// 完整写法 <template v-slot:default="slotProps"> {{ slotProps.user.name }} </template>
// 简写1（解构） <template v-slot="{ user }"> {{ user.name }} </template>
// 简写2（解构 + 重命名） <template v-slot="{ user: person }"> {{ person.name }} </template>
// 简写3（解构 + 默认值） <template v-slot="{ user = { name: '匿名' } }"> {{ user.name }} </template>

// ========== 4. 具名插槽 + 作用域 ==========
// 完整写法 <template v-slot:header="headerProps"> {{ headerProps.title }} </template>
// 简写 <template #header="{ title }"> {{ title }} </template>

// ========== 5. 动态插槽名 ==========
<template v-slot:[dynamicSlotName]> 动态插槽 </template>
<template #[dynamicSlotName]> <-- 简写 动态插槽 </template>
写法 语法 适用场景
具名插槽 #header 有多个插槽位置
默认插槽 v-slot 或 #default 只有一个插槽
作用域插槽 v-slot="{ data }" 需要接收子组件数据
组合使用 #header="{ title }" 具名 + 作用域

🌟 Demo 8: 插槽最佳实践

✅ 推荐做法

  • 提供默认内容：<slot>默认内容</slot> 增强组件健壮性
  • 语义化命名：header、footer、content，而不是 slot1、slot2
  • 作用域插槽用解构：v-slot="{ user }" 更简洁
  • 使用新语法：v-slot 和 # 简写（Vue 2.6+）
  • 文档注释：注明插槽名称、传递的数据结构
  • 单一职责：一个插槽只负责一块内容区域

❌ 避免的做法

❌ 过度使用插槽：简单组件不需要插槽，用props更清晰
❌ 插槽嵌套过深：会导致代码难以理解
❌ 忘记提供默认内容：父组件没传内容时会出现空白
❌ 混用新旧语法：在一个项目中保持一致
❌ 作用域插槽传递过多数据：只传必要的数据

使用场景 推荐方案 原因
简单固定文本 props props 更简洁直观
需要HTML结构 插槽 插槽支持任意内容
多个区域分发 具名插槽 明确内容位置
自定义渲染方式 作用域插槽 数据与UI分离
组件库开发 插槽 + props 灵活性与易用性兼顾

🎯 插槽 vs 通信方式对比

插槽不是组件通信！是内容分发！

📦 组件通信（数据传递）：
• props：父→子传数据
• $emit：子→父传数据
• provide/inject：祖→孙传数据

🎰 插槽（内容分发）：
• 默认插槽：父→子传HTML内容
• 具名插槽：父→子传多块HTML内容
• 作用域插槽：子→父传数据，父决定如何渲染

💡 核心区别：
• 通信 = 传数据（data、变量）
• 插槽 = 传内容（HTML、组件）
• 作用域插槽 = 两者结合！

// ===== 完整示例：组合使用所有特性 =====
// 子组件：卡片组件（props + 插槽） Vue.component('card', { props: { width: { type: String, default: '300px' }, shadow: { type: String, default: 'hover' } }, data() { return { timestamp: new Date().toLocaleString() } }, template: ` <div class="my-card" :style="{ width }"> <div class="card-header"> <slot name="header" :time="timestamp"> 默认标题 </slot> </div> <div class="card-body"> <slot>默认内容</slot> </div> <div class="card-footer"> <slot name="footer"> <button>确定</button> </slot> </div> </div> ` })
// 父组件使用 <card width="400px" shadow="always"> <!-- 具名插槽 + 作用域插槽 --> <template #header="{ time }"> <h2>用户信息</h2> <small>创建时间：{{ time }}</small> </template> <!-- 默认插槽 --> <p>姓名：张三</p> <p>年龄：25岁</p> <!-- 具名插槽 --> <template #footer> <button @click="save">保存</button> <button @click="cancel">取消</button> </template> </card>
