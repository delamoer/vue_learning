📤 组件通信：props（父传子）

Props - 父组件向子组件传递数据

💡 1. 什么是props？

props是父组件向子组件传递数据的通道
父组件
data: { userName: '张三', userAge: 18 }
⬇️ 通过 props 传递
子组件
props: ['userName', 'userAge'] 
// 父组件模板
<child-component :user-name="userName" :user-age="userAge"></child-component>

// 子组件定义
const ChildComponent = {
  props: ['userName', 'userAge'],
  template: `
    <div>
      <p>姓名：{{ userName }}</p>
      <p>年龄：{{ userAge }}</p>
    </div>
  `
}

演示效果：

✅ 核心理解
  • 父→子：数据流是单向的，从父组件流向子组件
  • 类比：就像函数的参数，父组件调用子组件时传入"参数"
  • 响应式：父组件数据变化，子组件会自动更新
  • 只读：子组件不能直接修改props

🎯 1.1 简单理解：props就是组件的"函数参数"

⭐ 最简单粗暴的理解方式
💡 一句话理解props

把子组件当成函数，props就是函数的参数，父组件调用子组件时按参数类型传入数据。

对比：函数 vs 组件

// 📌 函数的写法
function greet(name, age) {           // 定义参数
  console.log(`我是${name}，${age}岁`)
}
greet('张三', 18)                     // 调用函数，传入参数


// 📌 组件的写法（props就是参数）
const Greet = {
  props: ['name', 'age'],             // 定义"参数"
  template: `<p>我是{{ name }}，{{ age }}岁</p>`
}
// 使用组件时传入"参数"
<Greet name="张三" :age="18"></Greet>

更详细的对比：

函数 组件（props） 说明
function(name, age) props: ['name', 'age'] 定义参数/props
参数类型检查（TypeScript） props: { name: String } 类型限制
function(name = '匿名') props: { name: {default: '匿名'} } 默认值
必填参数（TypeScript） props: { name: {required: true} } 必填验证
greet('张三', 18) <Greet name="张三" :age="18"> 调用/使用
✅ 这个类比帮助理解：
  • props就是组件的"入参"：定义组件需要接收什么数据
  • 父组件"调用"子组件：在模板中使用子组件标签
  • 传入"参数"：通过属性传递数据给子组件
  • 子组件根据参数工作：根据不同的props显示不同的内容

📝 2. props的三种写法

从简单到复杂，满足不同场景需求

写法1：数组写法（简单接收）

props: ['name', 'age', 'gender']

// 特点：
// ✅ 简单快速
// ❌ 没有类型检查
// ❌ 没有默认值
// 适合：快速开发、原型验证

写法2：对象写法（类型限制）

props: {
  name: String,      // 限制为字符串
  age: Number,       // 限制为数字
  gender: String     // 限制为字符串
}

// 特点：
// ✅ 有类型检查（类型错误会警告）
// ❌ 没有默认值
// ❌ 不能设置必填
// 适合：需要类型检查的场景

写法3：完整对象写法（详细配置）⭐推荐

props: {
  name: {
    type: String,                // 类型
    required: true,              // 必填
    default: '匿名'              // 默认值（与required互斥）
  },
  age: {
    type: Number,
    default: 0,
    validator(value) {           // 自定义验证
      return value >= 0 && value <= 150
    }
  },
  hobbies: {
    type: Array,
    default() {                  // 数组/对象的默认值必须是函数
      return []
    }
  }
}

// 特点：
// ✅ 类型检查
// ✅ 可设置默认值
// ✅ 可设置必填
// ✅ 可自定义验证
// 适合：生产环境、组件库

演示效果：

💡 如何选择？
场景 推荐写法 原因
学习阶段 数组写法 简单直观，快速验证
个人项目 对象写法 有类型检查，避免低级错误
团队项目 完整对象写法 代码更健壮，作为文档使用
组件库 完整对象写法 需要严格的类型检查和默认值

🔄 3. 静态传递 vs 动态传递

理解什么时候用冒号(:)

静态传递（不加冒号）- 传字符串

<!-- 传递的都是字符串 -->
<child-component 
  name="张三" 
  age="18"          <!-- ❌ 这是字符串"18"，不是数字18 -->
  title="标题"
></child-component>

动态传递（加冒号）- 传JavaScript表达式 ⭐

<!-- 使用 v-bind 或 : 传递变量、表达式 -->
<child-component 
  :name="userName"        <!-- 传递变量 -->
  :age="18"               <!-- ✅ 传递数字18 -->
  :is-active="true"       <!-- 传递布尔值 -->
  :hobbies="['游泳', '跑步']"  <!-- 传递数组 -->
  :user="{name: '张三', age: 18}"  <!-- 传递对象 -->
  :calculate="1 + 2"      <!-- 传递表达式结果：3 -->
></child-component>
传递方式 写法 传递的是 适用场景
静态传递 name="张三" 字符串"张三" 传递固定的字符串
动态传递 :name="userName" 变量userName的值 传递变量、数字、布尔值、对象、数组

演示效果：

⚠️ 常见错误
// ❌ 错误：想传数字18，但忘记加冒号
<child-component age="18"></child-component>
// 结果：子组件收到的是字符串"18"

// ❌ 错误：想传布尔值true
<child-component is-active="true"></child-component>
// 结果：子组件收到的是字符串"true"

// ✅ 正确：传数字和布尔值要加冒号
<child-component :age="18" :is-active="true"></child-component>

📛 4. props命名规范

JavaScript用驼峰，HTML用短横线
// 在子组件的JavaScript中：用 camelCase（驼峰命名）
props: ['userName', 'userAge', 'isActive']

// 在父组件的HTML模板中：用 kebab-case（短横线命名）
<child-component 
  :user-name="name"      <!-- user-name 会自动转为 userName -->
  :user-age="age"        <!-- user-age 会自动转为 userAge -->
  :is-active="active"    <!-- is-active 会自动转为 isActive -->
></child-component>

// Vue 会自动进行转换：
user-name  → userName
user-age   → userAge
is-active  → isActive

演示效果：

💡 为什么要这样？
  • JavaScript规范：JavaScript中推荐用camelCase（驼峰）
  • HTML规范：HTML不区分大小写，所以用kebab-case（短横线）
  • 自动转换：Vue会自动在两种命名间转换，开发者无需关心

🚦 5. 单向数据流（重要）

为什么子组件不能修改props？
父组件
data: { count: 0 }
⬇️ props 单向流动
子组件
props: ['count']
⬆️ ❌ 不能直接修改props

❌ 错误示范：子组件直接修改props

const ChildComponent = {
  props: ['count'],
  methods: {
    increment() {
      this.count++;  // ❌ 错误！会报警告：Avoid mutating a prop directly
    }
  }
}

✅ 正确方案1：在data中创建副本

const ChildComponent = {
  props: ['count'],
  data() {
    return {
      localCount: this.count  // 创建本地副本
    }
  },
  methods: {
    increment() {
      this.localCount++;  // ✅ 修改本地副本
    }
  }
}

✅ 正确方案2：使用computed计算属性

const ChildComponent = {
  props: ['count'],
  computed: {
    doubleCount() {
      return this.count * 2  // ✅ 基于props计算新值
    }
  }
}

✅ 正确方案3：通过$emit通知父组件修改（最佳）

// 子组件：不直接修改，而是通知父组件
const ChildComponent = {
  props: ['count'],
  methods: {
    increment() {
      this.$emit('update-count', this.count + 1);  // ✅ 通知父组件
    }
  }
}

// 父组件：监听事件并修改数据
<child-component :count="count" @update-count="count = $event"></child-component>

演示效果：

⚠️ 为什么要单向数据流？
  • 数据流清晰：数据只能从父流向子，出问题容易定位
  • 避免混乱：如果多个子组件都能修改同一个props，会导致数据混乱
  • 职责分明：父组件负责管理数据，子组件负责展示数据
  • 便于维护：数据的变化只发生在父组件，维护更简单

✅ 6. props验证详解

如何对props进行严格验证？
const UserCard = {
  props: {
    // 基础类型检查
    name: String,
    age: Number,
    isVip: Boolean,
    
    // 多个可能的类型
    id: [String, Number],
    
    // 必填的字符串
    title: {
      type: String,
      required: true
    },
    
    // 带默认值的数字
    score: {
      type: Number,
      default: 0
    },
    
    // 带默认值的对象（必须用函数返回）
    user: {
      type: Object,
      default() {
        return { name: '游客' }
      }
    },
    
    // 带默认值的数组（必须用函数返回）
    hobbies: {
      type: Array,
      default() {
        return []
      }
    },
    
    // 自定义验证函数
    age: {
      type: Number,
      validator(value) {
        return value >= 0 && value <= 150
      }
    },
    
    // 自定义类型（构造函数）
    author: Person  // Person 是一个构造函数
  }
}

type可以是：

  • String - 字符串
  • Number - 数字
  • Boolean - 布尔值
  • Array - 数组
  • Object - 对象
  • Date - 日期
  • Function - 函数
  • Symbol - 符号
  • 自定义构造函数

  • ✅ 代码即文档：清楚地说明组件需要什么数据
  • ✅ 团队协作：其他人知道如何正确使用你的组件

🎯 7. 实战案例：用户卡片列表

完整的父子组件通信实战
📚 本节知识点总结

核心概念（必须掌握）

  • props是什么：父组件向子组件传递数据的通道
  • 单向数据流：数据从父流向子，子不能直接修改props
  • 静态vs动态：不加冒号传字符串，加冒号传JavaScript表达式

三种写法

写法 特点 适用场景
数组写法 简单快速 学习、快速原型
对象写法 类型检查 个人项目
完整对象写法 类型+默认值+验证 生产环境、团队项目

关键要点

  1. 传数字、布尔值、对象、数组时必须加冒号(:)
  2. JavaScript用驼峰，HTML用短横线，Vue自动转换
  3. 子组件不能直接修改props（单向数据流）
  4. 需要修改时：创建副本/用computed/通过$emit通知父组件
  5. 对象和数组的默认值必须用函数返回
