第一节

什么时候用 Vuex，什么时候不用

场景推荐方案理由
父子组件通信 props / $emit 关系简单，不需要全局
表单内部状态（输入值等） 组件 data 与其他组件无关，放 Vuex 是过度设计
弹窗/抽屉的开关状态 组件 data 或 provide/inject 通常只在父子间用
登录用户信息、Token Vuex 多处读取（导航栏、路由守卫、API 请求头）
购物车、通知未读数 Vuex 多个组件共享，需要实时更新
全局配置（语言、主题） Vuex 全应用生效，需要持久化
⭐ Vue 官方建议：如果你不确定是否需要 Vuex，那就不需要。等你感受到跨组件状态管理的痛苦时，再引入 Vuex。
第二节

State 持久化（vuex-persistedstate）

默认情况下，刷新页面 Vuex State 会重置。使用 vuex-persistedstate 插件可以把 State 同步到 localStorage：

// 安装 npm install vuex-persistedstate
// store/index.js import createPersistedState from 'vuex-persistedstate' export default new Vuex.Store({ plugins: [ // 默认：整个 state 都持久化 createPersistedState(), // 推荐：只持久化特定模块/字段 createPersistedState({ paths: ['user.token', 'user.id', 'cart.items'], // 白名单 key: 'my-app-store', // localStorage 的 key // 可选：使用 sessionStorage 而不是 localStorage storage: window.sessionStorage }) ] })
// 手动实现简单持久化（不需要额外依赖） const persisted = createPersistedState({ getState: (key) => JSON.parse(localStorage.getItem(key) || 'null'), setState: (key, state) => localStorage.setItem(key, JSON.stringify(state)), removeState: (key) => localStorage.removeItem(key) })
📌 注意：不要把密码、完整 token（应该放 httpOnly cookie）等敏感信息放 localStorage。
只持久化"用户偏好"（主题/语言）和"必要恢复状态"（如购物车）。
第三节

常见反模式（不要这样做）

❌ 反模式1：直接修改 State
// ❌ 直接赋值（绕过 Mutation，DevTools 无法追踪） this.$store.state.count = 5 this.$store.state.user.name = 'Alice' // ✅ 正确方式：commit Mutation this.$store.commit('SET_COUNT', 5) this.$store.commit('SET_USER_NAME', 'Alice')
❌ 反模式2：在 Mutation 里做异步
// ❌ Mutation 里写异步（DevTools 时光旅行功能失效） mutations: { FETCH_USER(state, userId) { fetch(`/api/user/${userId}`).then(r => r.json()).then(user => { state.user = user // 问题：何时执行未知 }) } } // ✅ 异步逻辑放 Action actions: { async fetchUser({ commit }, userId) { const user = await api.getUser(userId) commit('SET_USER', user) } }
❌ 反模式3：在组件里做业务逻辑然后 commit
// ❌ 业务逻辑放在组件里（重复、难测试） async addToCart(product) { const stock = await api.getStock(product.id) if (stock > 0) { this.$store.commit('ADD_TO_CART', product) } // 另一个组件也有一样的代码 → 重复 } // ✅ 业务逻辑封装在 Action 里 → 多组件复用 async handleAdd(product) { await this.$store.dispatch('cart/addToCart', product) }
❌ 反模式4：一个 Mutation 修改不相关的多个字段
// ❌ 一个 mutation 做了太多事，难以追踪哪个字段为什么变 mutations: { UPDATE_ALL(state, payload) { state.user = payload.user state.cart = payload.cart state.settings = payload.settings } } // ✅ 每个 Mutation 只做一件事 mutations: { SET_USER(state, user) { state.user = user }, SET_CART(state, cart) { state.cart = cart }, SET_SETTINGS(state, settings) { state.settings = settings } }
第四节

Vuex + Vue Router 结合（权限控制）

// router/index.js — 全局前置守卫读取 Vuex 状态 import store from '@/store' router.beforeEach((to, from, next) => { const isLoggedIn = store.getters['user/isLoggedIn'] const requiresAuth = to.meta.requiresAuth const requiresAdmin = to.meta.requiresAdmin const isAdmin = store.getters['user/isAdmin'] if (requiresAuth && !isLoggedIn) { // 未登录跳登录页，记录来源 next({ path: '/login', query: { redirect: to.fullPath } }) } else if (requiresAdmin && !isAdmin) { // 无权限跳 403 next({ path: '/403' }) } else { next() } })
// 路由配置中添加 meta { path: '/admin', component: AdminView, meta: { requiresAuth: true, requiresAdmin: true, title: '管理后台' } }
// 登录成功后跳回来源页 async handleLogin() { await this.$store.dispatch('user/login', this.form) const redirect = this.$route.query.redirect || '/' this.$router.push(redirect) }
第五节

Vuex 4 / Pinia — Vue 3 时代

Vue 3 推荐使用 Pinia（下一代官方状态库，Vuex 5 的继任者）。如果你在学 Vue 2，了解即可：

对比项Vuex 3 (Vue 2)Pinia (Vue 3)
核心概念state / getters / mutations / actionsstate / getters / actions（没有 mutations）
修改 state必须通过 commit Mutation可以在 action 里直接修改，也可以 $patch
TypeScript支持差，类型推断弱完美 TypeScript 支持
模块化modules + namespaced多个独立 store，天然无命名冲突
Devtools✅✅（更好）
包大小~8KB~1KB
Pinia 写法预览（Vue 3）
// stores/user.js (Pinia) import { defineStore } from 'pinia' export const useUserStore = defineStore('user', { state: () => ({ id: null, name: '', token: '' }), getters: { isLoggedIn: (state) => !!state.id }, actions: { async login(credentials) { const data = await api.login(credentials) // 直接修改 state，不需要 mutation this.token = data.token this.id = data.user.id this.name = data.user.name } } })
