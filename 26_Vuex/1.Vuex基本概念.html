第一节

为什么需要 Vuex？

在学习 Vue Router 时，我们已经能在多个页面之间跳转。但一个新问题出现了：多个无关联组件之间怎么共享数据？

没有 Vuex 时的困境
❌ 跨组件传数据很麻烦
  • 父子通信：props + $emit ✓
  • 兄弟通信：Event Bus（容易失控）
  • 祖孙通信：provide/inject（不响应式）
  • 跨页面通信：localStorage？❌ 不够优雅
  • 多层嵌套：props 地狱
✅ 哪些状态需要共享
  • 🔐 登录用户信息（多处读取）
  • 🛒 购物车数量（导航栏 + 购物车页）
  • 🌙 主题/语言设置（全局生效）
  • 📢 消息通知数量（随时更新）
  • 🔑 用户权限信息（路由守卫用）
Vuex 的核心思想

把这些需要在多个组件之间共享的状态，统一放到一个叫做 Store（仓库）的地方集中管理。任何组件都可以直接读取，也可以通知 Store 修改状态，修改后所有依赖该状态的组件都会自动更新。

Vuex 的核心理念
组件 A 组件 B 组件 C
↕   读取 / 提交变更
Vuex Store（单一数据源）
⭐ Vuex 的哲学来自 Flux / Redux：单向数据流，状态变化可追踪，调试更方便。
口诀：组件 读 State，组件 通过 Action → Mutation 改 State，State 变化自动刷新视图。
第二节

Vuex 五大核心概念

Vuex Store 由 5 个部分组成，记住下面这张图就记住了 Vuex 的全部：

Vuex 数据流向图
Vue 组件
    ⬇ dispatch('action名', 载荷)            ⬆ 读取 state / getters
Actions（动作） — commit → Mutations（变更） — mutate → State（状态）
        可做异步操作                 只能同步                   唯一数据源
Getters（计算状态） ← 基于 State 派生，类似 computed
Modules（模块） ← 将 Store 拆分为多个独立模块
概念类比作用对应 Vue 选项
State 仓库的"库存数据" 存放共享状态，唯一数据源 data
Getters 仓库的"统计报表" 从 State 派生出新数据，有缓存 computed
Mutations 仓库的"入库单" 唯一可以直接修改 State 的地方，必须同步 methods（同步）
Actions 仓库的"采购员" 处理异步操作，最终 commit Mutation methods（异步）
Modules 仓库的"分区" 将大 Store 拆分为多个小模块 —
⚠️ 最重要的规则：State 只能通过 Mutation 修改！
不能直接写 this.$store.state.count = 5（虽然技术上可以但绝对不要）。
这样做的目的是让状态变化可追踪（Vuex DevTools 能记录每次变更）。
第三节

第一个 Vuex Store（安装与基础配置）

安装
# Vue 2 对应 Vuex 3 npm install vuex@3 # Vue 3 对应 Vuex 4 npm install vuex@4
创建 Store（src/store/index.js）
import Vue from 'vue' import Vuex from 'vuex' Vue.use(Vuex) // 注册插件 const store = new Vuex.Store({ // State：共享的数据 state: { count: 0, username: '', cartItems: [] }, // Getters：从 state 派生的计算属性 getters: { cartCount(state) { return state.cartItems.length }, // 接收其他 getter 作为第二参数 cartTotal(state, getters) { return state.cartItems.reduce((sum, item) => sum + item.price, 0) } }, // Mutations：同步修改 state（唯一合法途径） mutations: { INCREMENT(state) { state.count++ }, SET_USERNAME(state, name) { // 第二参数叫"载荷（payload）" state.username = name }, ADD_TO_CART(state, item) { state.cartItems.push(item) } }, // Actions：可以异步，最终调用 mutation actions: { async fetchUser({ commit }, userId) { const user = await api.getUser(userId) commit('SET_USERNAME', user.name) } } }) export default store
挂载到 Vue 实例（main.js）
import Vue from 'vue' import App from './App.vue' import router from './router' import store from './store' // ← 引入 store new Vue({ router, store, // ← 挂载到实例，之后所有组件都可以通过 this.$store 访问 render: h => h(App) }).$mount('#app')
第四节

在组件中使用 Store

读取 State 和 Getters
// 在组件中通过 this.$store 访问 computed: { // 读取 state count() { return this.$store.state.count }, username() { return this.$store.state.username }, // 读取 getter（已缓存，等同于 computed） cartCount() { return this.$store.getters.cartCount }, cartTotal() { return this.$store.getters.cartTotal } }
提交 Mutation（同步修改）
methods: { add() { // commit('mutation名称'[, 载荷]) this.$store.commit('INCREMENT') this.$store.commit('SET_USERNAME', 'Alice') // 对象写法（载荷是对象） this.$store.commit({ type: 'ADD_TO_CART', item: { id: 1, price: 99 } }) } }
分发 Action（异步操作）
methods: { async loadUser() { // dispatch('action名称'[, 载荷]) await this.$store.dispatch('fetchUser', this.userId) } }
📌 $store 在任意组件中都可以使用，因为我们在 main.js 里把 store 注入了 Vue 实例。
后面会学到辅助函数（mapState / mapGetters / mapMutations / mapActions），可以大幅简化写法。
第五节

Vuex vs Vue Router：各司其职

对比项Vue RouterVuex
解决什么问题页面导航 / URL 映射跨组件状态共享
核心对象$router（导航）/ $route（当前路由信息）$store（全局状态仓库）
数据流向URL → 组件渲染组件 → Action → Mutation → State → 组件
常用 APIpush / replace / beforeEachcommit / dispatch / mapState
典型场景从列表跳详情、登录重定向购物车、用户信息、消息数量
配合使用路由守卫里读取 Vuex 用户权限，决定是否允许访问某路由
✅ 两者经常配合：在 router.beforeEach 里读取 store.getters.isLoggedIn 来做权限判断 — 这是企业项目中最常见的模式！
第六节

Vuex 完整数据流图（口诀速记）

组件需要读数据： 组件 → this.$store.state.xxx 直接读 组件 → this.$store.getters.xxx 读计算后的值 组件需要改数据： 同步操作： 组件 → this.$store.commit('MUTATION_NAME', payload) ↓ Mutation 直接修改 state 异步操作（API 请求等）： 组件 → this.$store.dispatch('actionName', payload) ↓ Action 执行异步逻辑 ↓ commit Mutation ↓ Mutation 修改 state ↓ 视图自动更新 ✅
⭐ 什么时候用 Action，什么时候用 Mutation？
• 需要调用 API / setTimeout / Promise → 用 Action
• 只是简单修改数据 → 直接 commit Mutation（不必走 Action）
• 口诀：有副作用（异步）用 Action，纯数据变更用 Mutation
