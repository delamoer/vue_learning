Vuex · Modules 模块化

第一节

为什么需要模块化

当应用变大，所有状态堆在一个 Store 里会变得难以维护：

  • state 里有几十个属性，混在一起难以理解
  • mutations / actions 几百行，命名容易冲突
  • 团队协作时，多人同时修改 store/index.js 频繁冲突

Modules 允许将 Store 拆分为多个独立子模块，每个模块拥有自己的 state、getters、mutations、actions。

⭐ 典型拆分方式：按业务领域拆（user 模块、cart 模块、orders 模块），而不是按技术层级拆。
第二节

模块定义与注册

定义子模块（store/modules/user.js）
// store/modules/user.js export default { namespaced: true, // ← 开启命名空间（强烈推荐） state: () => ({ // 模块的 state 推荐写成函数（避免引用共享） id: null, name: '', token: localStorage.getItem('token') || '', avatar: '' }), getters: { isLoggedIn: state => !!state.id, displayName: state => state.name || '未登录' }, mutations: { SET_USER(state, user) { Object.assign(state, user) }, SET_TOKEN(state, token) { state.token = token localStorage.setItem('token', token) }, CLEAR(state) { state.id = null; state.name = ''; state.token = '' localStorage.removeItem('token') } }, actions: { async login({ commit }, credentials) { const { data } = await axios.post('/api/login', credentials) commit('SET_TOKEN', data.token) commit('SET_USER', data.user) }, logout({ commit }) { commit('CLEAR') } } }
注册到根 Store（store/index.js）
import Vue from 'vue' import Vuex from 'vuex' import user from './modules/user' import cart from './modules/cart' import order from './modules/order' Vue.use(Vuex) export default new Vuex.Store({ // 根级的 state/getters（全局共享的极少量状态） state: { globalLoading: false }, mutations: { SET_GLOBAL_LOADING(state, v) { state.globalLoading = v } }, // 注册模块 modules: { user, cart, order } })
第三节

命名空间（namespaced: true）

不开启命名空间时，模块的 getters/mutations/actions 会合并到全局，容易命名冲突。推荐全部模块都开启 namespaced: true。

操作无命名空间有命名空间（user 模块）
读 state$store.state.user.id$store.state.user.id（一样）
读 getter$store.getters.isLoggedIn$store.getters['user/isLoggedIn']
commit$store.commit('SET_USER', u)$store.commit('user/SET_USER', u)
dispatch$store.dispatch('login', c)$store.dispatch('user/login', c)
⚠️ 命名空间的分隔符是 /，格式是 '模块名/TYPE'。
嵌套模块可以多层：'shop/cart/ADD'
第四节

在组件中访问模块（带命名空间）

直接访问
computed: { userId() { return this.$store.state.user.id }, // state 不受命名空间影响 isLoggedIn() { return this.$store.getters['user/isLoggedIn'] }, cartCount() { return this.$store.getters['cart/count'] } }, methods: { login(cred) { return this.$store.dispatch('user/login', cred) }, addItem(item){ this.$store.commit('cart/ADD', item) } }
mapState / mapGetters / mapActions / mapMutations + 命名空间
import { mapState, mapGetters, mapActions, mapMutations } from 'vuex' computed: { // 方式1：第一参数传模块名（字符串） ...mapState('user', ['id', 'name', 'token']), ...mapGetters('user', ['isLoggedIn', 'displayName']), // 方式2：createNamespacedHelpers（整个组件只用一个模块时最简洁） }, methods: { ...mapActions('user', ['login', 'logout']), ...mapMutations('cart', ['ADD', 'REMOVE', 'CLEAR']) }
createNamespacedHelpers（组件专注单一模块时最优）
import { createNamespacedHelpers } from 'vuex' const { mapState, mapGetters, mapActions } = createNamespacedHelpers('user') // 之后 mapState/mapGetters/mapActions 都自动带上 'user/' 前缀 computed: { ...mapState(['id', 'name']), // → state.user.id, state.user.name ...mapGetters(['isLoggedIn']) // → getters['user/isLoggedIn'] }, methods: { ...mapActions(['login', 'logout']) // → dispatch('user/login') }
第五节

模块间通信（rootState / rootGetters）

模块内的 getters 和 actions 可以通过额外参数访问根 state 和其他模块的数据：

Getters 中访问根 state
// store/modules/cart.js getters: { // getter 参数：(localState, localGetters, rootState, rootGetters) cartWithUserInfo(state, getters, rootState, rootGetters) { const user = rootState.user // 访问 user 模块的 state const isVip = rootGetters['user/isVip'] // 访问 user 模块的 getter return { items: state.items, owner: user.name, discount: isVip ? 0.9 : 1.0 } } }
Actions 中访问根 store / 调用其他模块的 Action
// store/modules/cart.js actions: { // action 中 context 也可解构 rootState / rootGetters async checkout({ state, commit, dispatch, rootState, rootGetters }) { const userId = rootState.user.id // 读 user 模块 state if (!rootGetters['user/isLoggedIn']) { // 调用根级 action（不加命名空间） dispatch('showLoginDialog', null, { root: true }) return } const { data } = await api.checkout({ userId, items: state.items }) commit('CLEAR') // commit 本模块的 mutation // 调用其他模块的 action dispatch('order/fetchList', null, { root: true }) } }
📌 跨模块调用规则：
• 在模块内 commit/dispatch 时，不加路径 → 调用本模块的 mutation/action
• 加 { root: true } 选项 → 调用根级或其他模块（加全路径 'order/fetchList'）
第六节

大型项目 Store 目录结构

src/store/ ├── index.js ← 根 Store，注册所有模块 ├── mutation-types.js ← 全局通用 Mutation 常量 ├── plugins.js ← Vuex 插件（如 persisted state） └── modules/ ├── user/ │ ├── index.js ← 模块入口（汇总 state/getters/mutations/actions） │ ├── state.js │ ├── getters.js │ ├── mutations.js │ ├── actions.js │ └── types.js ← 该模块专用常量 ├── cart/ │ └── index.js ← 简单模块可以合并在一个文件 └── order/ └── index.js
// store/modules/user/index.js — 拆分写法示例 import state from './state' import getters from './getters' import mutations from './mutations' import actions from './actions' export default { namespaced: true, state, getters, mutations, actions }
✅ 建议：
• 小型项目（<5个模块，每个模块<100行）：直接写在 modules/xxx.js 单文件里
• 中大型项目：每个模块建子目录，按 state/getters/mutations/actions 拆分
• namespaced: true 永远都要加，防止命名冲突
