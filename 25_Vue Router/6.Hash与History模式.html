Vue Router · Hash 与 History 模式

第一节

Hash 模式

URL 长什么样
// Hash 模式的 URL（默认） http://localhost:8080/#/home http://localhost:8080/#/user/42 http://localhost:8080/#/search?kw=vue // ↑ # 后面的部分叫做 hash
工作原理

浏览器中，URL 的 # 及其后面的内容叫 hash。

  • ① hash 变化时，浏览器不会向服务器发请求（服务器永远只收到 /）
  • ② 浏览器会触发 hashchange 事件
  • ③ Vue Router 监听 hashchange，根据 hash 渲染对应组件
// Vue Router 内部大致逻辑（简化） window.addEventListener('hashchange', () => { const hash = location.hash // "#/user/42" const path = hash.slice(1) // "/user/42" // 根据 path 找对应路由，渲染组件... })
✅ Hash 模式的最大优点：不需要服务器做任何配置，因为 hash 从来不会发到服务器端。打开 dist/index.html 直接双击也能用（本地文件）。
第二节

History 模式

URL 长什么样
// History 模式的 URL（更漂亮） http://localhost:8080/home http://localhost:8080/user/42 http://localhost:8080/search?kw=vue // 没有 #，就像普通多页应用的 URL
工作原理

利用 HTML5 的 History API：pushState 和 replaceState。

// History API 可以改变 URL 而不引起页面刷新 history.pushState({}, '', '/user/42') // URL 变成 /user/42，但页面不刷新 history.replaceState({}, '', '/home') // URL 替换为 /home，无历史记录 // 监听前进/后退（popstate 事件） window.addEventListener('popstate', () => { // 根据 location.pathname 渲染组件 })
开启 History 模式
const router = new VueRouter({ mode: 'history', // ← 只需要加这一行 routes: [...] }) // 默认是 hash 模式（mode: 'hash'），不用写
⚠️ History 模式的问题：
用户直接访问 http://example.com/user/42（刷新或直接输入地址），浏览器会向服务器请求 /user/42 这个路径。但服务器上只有 index.html，/user/42 根本不存在，就会返回 404！
第三节

History 模式的服务器配置

解决方案：让服务器对任何路径都返回 index.html，然后让前端 Vue Router 来解析路径。

Nginx 配置
server { listen 80; server_name example.com; root /var/www/dist; location / { try_files $uri $uri/ /index.html; # 意思：先找对应文件，找不到就返回 index.html } }
Node.js + Express
const express = require('express') const history = require('connect-history-api-fallback') const app = express() // 关键：放在静态文件服务之前 app.use(history()) app.use(express.static('dist')) app.listen(3000)
Vue CLI devServer（开发环境）
// vue.config.js — 开发服务器会自动处理，但可以显式配置 module.exports = { devServer: { historyApiFallback: true // 开发时自动回退到 index.html } }
📌 Vue CLI 的开发服务器默认已配置 historyApiFallback，所以开发时你感觉不到差异。问题只会在打包部署到真实服务器后出现。
第四节

两种模式全面对比

对比项Hash 模式History 模式
URL 形态 /#/user/42 /user/42
URL 美观度 有 # 符号，不够优雅 ✅ 干净，像普通 URL
服务器是否收到路径 ❌ 服务器只收到 /（hash 不发送） ✅ 服务器会收到完整路径
需要服务器配置 ❌ 不需要（静态文件服务即可） ✅ 需要（否则刷新 404）
直接打开 index.html ✅ 可以（适合无服务器部署） ❌ 不可以（需要 HTTP 服务器）
SEO 友好性 差（爬虫不能抓取 hash 后的内容） ✅ 好（正常 URL，可被爬虫抓取）
浏览器兼容性 ✅ 极好（所有浏览器） 良好（IE10+，需要 HTML5 History API）
分享 URL 时 带 # 号略丑 ✅ 正常链接
第五节

如何选择？

选 Hash 模式
  • 需要部署到纯静态服务器（如 GitHub Pages、CDN 直接托管）
  • 服务器是第三方托管，无法配置
  • 需要支持 IE 9 等老旧浏览器
  • 项目不在乎 SEO（内部管理系统、后台）
选 History 模式（推荐）
  • 能控制服务器配置（Nginx、Node.js 等）
  • URL 美观是需求之一
  • 对外的 C 端产品，SEO 有要求
  • 现代项目的默认选择
⭐ 实际项目结论：
有服务器控制权 → 用 History 模式（更专业，URL 干净）
纯静态托管（GitHub Pages、直接打开 HTML 文件）→ 用 Hash 模式（零配置）

我们的 vue2-sfc-demo 和 vue2-router-demo 均使用 History 模式，因为 Vue CLI devServer 已自动处理。
