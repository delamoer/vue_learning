第一节

为什么需要 Nginx？开发 vs 生产的差异

💻 npm run serve（开发）
  • ✦ webpack-dev-server 内置服务器
  • ✦ 自动处理 History 路由回退
  • ✦ 自带 devServer.proxy 反向代理
  • ✦ Hot reload、sourcemap 等开发工具
  • ✦ 不能用于生产环境（性能/安全）
🌐 上线后（生产）
  • ✦ 运行 npm run build 生成 dist/
  • ✦ dist 里全是静态文件（html/js/css）
  • ✦ 需要 Nginx（或 Apache/CDN）来托管
  • ✦ History 路由、API 代理都要手动配
📌 Nginx 是一个高性能 HTTP 服务器，在前端部署中主要承担三件事：
① 托管静态文件（把 dist 暴露到网络）   ② 处理 History 路由（避免刷新 404）   ③ 反向代理 API（把 /api 转发给后端服务）
第二节

Step 1 — 打包前端项目

运行构建命令
# 在项目根目录执行 npm run build # 构建完成后，会生成 dist/ 目录 # 这个目录里的全部内容就是要上传到服务器的东西
dist 目录结构
dist/ ├── index.html # 入口文件（唯一 HTML） ├── favicon.ico └── static/ （或 assets/，取决于 Vue CLI 版本） ├── css/ │ └── app.xxx.css # 样式文件（hash 命名，长缓存） ├── js/ │ ├── app.xxx.js # 应用代码 │ ├── chunk-xxx.js # 懒加载路由分包 │ └── chunk-vendors.xxx.js # 第三方库（vue、vue-router 等） └── img/
⭐ publicPath 配置：如果你的应用不是部署在域名根路径，而是子路径（如 https://example.com/myapp/），需要在 vue.config.js 中设置 publicPath: '/myapp/'，并且路由的 base 选项也要一致。
// vue.config.js（子路径部署时） module.exports = { publicPath: process.env.NODE_ENV === 'production' ? '/myapp/' // 生产环境子路径 : '/' // 开发环境根路径 } // router/index.js（对应配置 base） const router = new VueRouter({ mode: 'history', base: process.env.NODE_ENV === 'production' ? '/myapp/' : '/', routes })
第三节

Step 2 — 最小可用 Nginx 配置

把 dist/ 上传到服务器（例如 /var/www/myapp），然后写 Nginx 配置文件：

基础配置（支持 History 路由）
server { listen 80; server_name example.com; # 换成你的域名或服务器 IP # dist 文件夹路径 root /var/www/myapp; index index.html; location / { # 关键配置：找不到文件时回退到 index.html # 这样刷新 /articles/3 不会报 404 try_files $uri $uri/ /index.html; } }
⚠️ try_files $uri $uri/ /index.html 是 History 模式部署的核心配置。
含义：先找真实文件（$uri）→ 再找目录（$uri/）→ 都找不到则返回 index.html，让前端路由接管。
验证配置 & 重载
# 测试配置文件语法是否正确 nginx -t # 重载配置（不中断服务） nginx -s reload # 或者用 systemd 管理 systemctl reload nginx
第四节

Step 3 — 反向代理 API

前端打包后无法再用 vue.config.js 里的 devServer.proxy，必须在 Nginx 里配反向代理。

场景：前端部署在 80 端口，后端跑在 3000 端口
server { listen 80; server_name example.com; root /var/www/myapp; index index.html; # ① 前端静态资源 + History 路由回退 location / { try_files $uri $uri/ /index.html; } # ② 把 /api/* 转发给后端服务 location /api/ { proxy_pass http://127.0.0.1:3000/; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; } }
前端代码中 API 请求写法对应关系
前端请求Nginx 转发到说明
axios.get('/api/users')http://127.0.0.1:3000/usersproxy_pass 末尾有 / → 截掉 /api 前缀
axios.post('/api/login')http://127.0.0.1:3000/login同上
📌 proxy_pass 末尾斜线的区别：
proxy_pass http://127.0.0.1:3000/（有斜线）→ /api/users 变成 /users（截掉 /api）
proxy_pass http://127.0.0.1:3000（无斜线）→ /api/users 变成 /api/users（完整转发）
选哪种取决于你后端路由是否带 /api 前缀。
与 vue.config.js devServer.proxy 的对比
配置位置生效环境原理
vue.config.js devServer.proxy开发环境（npm run serve）webpack-dev-server 内置代理
Nginx location /api/生产环境（npm run build 后）Nginx 反向代理
第五节

Step 4 — Gzip 压缩与静态资源缓存

Vue 打包生成的 JS 文件往往有数百 KB，开启 Gzip 后体积通常能压缩到 1/3，页面加载更快。

开启 Gzip
# /etc/nginx/nginx.conf 或 server 块中加入 gzip on; gzip_min_length 1k; # 小于 1k 的文件不压缩 gzip_comp_level 6; # 压缩级别 1-9，6 是性能/压缩比均衡点 gzip_types text/plain text/css text/javascript application/javascript application/json application/xml image/svg+xml; gzip_vary on; # 告诉代理服务器缓存两种版本
静态资源长缓存（hash 文件名策略）

Vue CLI 打包生成的 JS / CSS 文件名中包含 hash（如 app.3f1a2b.js），内容不变 hash 不变，内容改变 hash 改变。利用这个特性，可以放心开启长缓存：

server { ... location / { try_files $uri $uri/ /index.html; } # index.html：永远不缓存（或极短缓存） # 因为它引用了带 hash 的 js/css，每次部署都要拿最新的 location = /index.html { add_header Cache-Control "no-cache, no-store, must-revalidate"; } # 带 hash 的 js/css：1 年长缓存 location ~* \.(js|css)$ { expires 1y; add_header Cache-Control "public, immutable"; } # 图片字体：适当缓存 location ~* \.(png|jpg|jpeg|gif|ico|svg|woff2|ttf)$ { expires 30d; add_header Cache-Control "public"; } }
✅ 这组缓存策略的逻辑：
• index.html 禁止缓存 → 用户每次打开都拿最新的，保证加载最新的 js/css hash 引用
• 带 hash 文件名的 js/css 永久缓存 → 内容没变就不重新下载，极大加速二次访问
第六节

HTTPS 配置（Let's Encrypt 免费证书）

生产环境强烈建议开启 HTTPS，现代浏览器对非 HTTPS 站点会有安全警告，且 PWA / Service Worker 等功能依赖 HTTPS。

使用 Certbot 获取 Let's Encrypt 免费证书
# 安装 certbot（Ubuntu/Debian） apt install certbot python3-certbot-nginx # 自动申请证书并修改 Nginx 配置 certbot --nginx -d example.com -d www.example.com # certbot 会自动在 Nginx 配置里加上 SSL 相关内容 # 证书有效期 90 天，通过 cron 任务自动续期
手动 HTTPS 配置示例
# HTTP → 强制跳转 HTTPS server { listen 80; server_name example.com; return 301 https://$host$request_uri; } server { listen 443 ssl http2; server_name example.com; ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem; root /var/www/myapp; index index.html; location / { try_files $uri $uri/ /index.html; } location /api/ { proxy_pass http://127.0.0.1:3000/; } }
第七节

常见问题排查

❌ 刷新页面出现 404（Not Found）
原因：History 模式下 Nginx 直接找对应文件，找不到就 404。
解决：在 location / 里加上 try_files $uri $uri/ /index.html;
❌ API 请求出现 502 Bad Gateway
原因：Nginx 无法连接到后端服务（后端没起来，或端口/地址写错）。
排查：
1. 确认后端服务是否在运行：curl http://127.0.0.1:3000/api/users
2. 检查 proxy_pass 地址是否正确
3. 查看 Nginx 错误日志：tail -f /var/log/nginx/error.log
❌ API 请求出现 404，但后端服务正常
原因：proxy_pass 末尾斜线导致路径转换出错。
排查：弄清楚后端路由是否带 /api 前缀，再决定 proxy_pass 末尾是否加斜线（详见第四节）。
❌ 部署后页面空白（白屏）
原因：最常见是 JS/CSS 路径 404，通常是 publicPath 配置不对。
排查：打开浏览器 DevTools → Network 面板，看哪些资源 404 → 检查路径是否和 publicPath / base 一致。
❌ 修改代码重新部署后浏览器还是旧版本
原因：浏览器缓存了旧的 index.html，加载了旧的 js hash。
解决：确保 index.html 配置了 Cache-Control: no-cache（见第五节）。
❌ nginx -t 报错 "unknown directive"
原因：配置文件语法错误，或使用了未安装的 Nginx 模块（如 gzip_static 需要额外模块）。
解决：仔细看错误提示的行号，对照语法检查。
第八节

完整生产配置模板（可直接复用）

结合前几节，这是一份完整的生产级配置，覆盖 History 路由 / API 代理 / Gzip / 缓存策略 / HTTPS 跳转：

⭐ 该配置同时存放在 nginx.conf.example 文件中，可直接复制修改 server_name 和 root 路径使用。
# ==================================================== # Vue 2 项目 Nginx 生产配置模板 # 修改：server_name、root、proxy_pass 三处即可使用 # ==================================================== # HTTP → HTTPS 跳转（如无 HTTPS 可删除此 server 块） server { listen 80; server_name example.com; return 301 https://$host$request_uri; } server { listen 443 ssl http2; server_name example.com; # ← 改成你的域名 # SSL 证书（Let's Encrypt） ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem; # Gzip 压缩 gzip on; gzip_min_length 1k; gzip_comp_level 6; gzip_types text/plain text/css application/javascript application/json image/svg+xml; # dist 目录 root /var/www/myapp; # ← 改成你的 dist 路径 index index.html; # index.html：禁止缓存（确保每次拿最新版本） location = /index.html { add_header Cache-Control "no-cache, no-store, must-revalidate"; } # 带 hash 的 js/css：1 年长缓存 location ~* \.(js|css)$ { expires 1y; add_header Cache-Control "public, immutable"; } # 图片字体 location ~* \.(png|jpg|jpeg|gif|ico|svg|woff2|ttf|eot)$ { expires 30d; add_header Cache-Control "public"; } # API 反向代理（把 /api/* 转发给后端 Node.js / Spring Boot 等） location /api/ { proxy_pass http://127.0.0.1:3000/; # ← 改成你的后端地址 proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection 'upgrade'; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_cache_bypass $http_upgrade; } # 前端路由 + History 模式回退（必须放在最后） location / { try_files $uri $uri/ /index.html; } }
