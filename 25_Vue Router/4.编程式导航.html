第一节

声明式导航 vs 编程式导航

📌 声明式导航

用 <router-link> 标签，写在模板中。

适合：普通导航链接、菜单。

<router-link to="/home">首页</router-link>
⚡ 编程式导航

用 this.$router 方法，写在 JS 逻辑中。

适合：表单提交后跳转、权限判断后跳转、按条件跳转等。

this.$router.push('/home')
第二节

$router.push()

push 会向历史记录栈中推入一条新记录，用户可以点浏览器"后退"回来。

字符串写法
this.$router.push('/home') this.$router.push('/user/42') this.$router.push('/search?kw=vue')
对象写法（推荐）
// 用 path this.$router.push({ path: '/home' }) // 用命名路由 + params this.$router.push({ name: 'user', params: { id: 42 } }) // 用 path + query（params 在 path 下会被忽略，query 不受影响） this.$router.push({ path: '/search', query: { kw: 'vue', page: 1 } }) // 带 hash this.$router.push({ path: '/about', hash: '#team' })
push 的回调（成功/失败）
// Vue Router 3：push 返回 undefined（不是 Promise） // 需要用回调获取导航结果 this.$router.push('/home', () => { console.log('导航完成') }, (err) => { console.log('导航失败', err) }) // Vue Router 4（Vue 3）：push 返回 Promise await this.$router.push('/home')
⚠️ 常见报错：NavigationDuplicated
在 Vue Router 3 中，重复导航到同一路由会报错（比如多次点击同一导航）。
解决方案：在 push 后加空的 .catch(() => {})，或者升级到不会报错的 Router 4。
// 临时解决重复导航报错（Vue Router 3 常见做法） this.$router.push('/home').catch(() => {})
第三节

$router.replace() 和 $router.go()

replace()：替换当前历史记录

replace 和 push 用法完全相同，区别在于它不会留下历史记录——用户无法通过后退返回替换前的页面。

// 用法与 push 一致 this.$router.replace('/login') this.$router.replace({ name: 'home' })
📌 什么时候用 replace：
• 登录后跳转首页（不希望用户后退回登录页）
• 表单提交成功后跳转结果页（不希望用户后退后重复提交）
• 重定向时（比如未登录跳转到 /login）
go()、back()、forward()
// 在历史记录中前进/后退 this.$router.go(-1) // 后退一步，等同于浏览器后退 this.$router.go(1) // 前进一步 this.$router.go(-3) // 后退三步 this.$router.go(0) // 刷新当前页 // 语义化简写 this.$router.back() // 等同于 go(-1) this.$router.forward() // 等同于 go(1)
全部方法速查
方法历史记录适用场景
$router.push(location)增加一条记录普通导航跳转
$router.replace(location)替换当前记录登录跳转、表单提交后跳转
$router.go(n)在已有记录中移动后退/前进按钮
$router.back()go(-1) 简写返回上一页按钮
$router.forward()go(1) 简写前进按钮
第四节

实际场景示例

场景1：表单登录后跳转
methods: { async handleLogin() { try { await this.login(this.form) // 登录成功：replace 跳首页，不留登录页历史记录 this.$router.replace({ name: 'home' }) } catch (err) { this.errorMsg = '账号或密码错误' } } }
场景2：带参数跳转文章详情
methods: { goToArticle(articleId) { this.$router.push({ name: 'article-detail', params: { id: articleId } }) }, goToSearch(keyword) { this.$router.push({ path: '/search', query: { kw: keyword, page: 1 } }) } }
场景3：路由跳转前判断权限
methods: { goToAdmin() { if (!this.isLoggedIn) { // 未登录：跳转到登录页，同时记录目标地址 this.$router.push({ path: '/login', query: { redirect: this.$route.fullPath } }) return } this.$router.push('/admin') } } // 登录成功后：读取 redirect 参数，跳转到原目标页 const redirect = this.$route.query.redirect || '/' this.$router.replace(redirect)
✅ 最佳实践：权限跳转（未登录重定向）推荐放在路由守卫（router.beforeEach）里统一处理，而不是在每个组件里写。详见下一章：路由守卫。
