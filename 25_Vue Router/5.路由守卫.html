第一节

路由守卫是什么

路由守卫（Navigation Guards）是 Vue Router 提供的钩子函数，允许你在路由跳转发生前后执行逻辑，比如：

  • ✦ 检查用户是否已登录（未登录则重定向到 /login）
  • ✦ 检查用户是否有权限访问某个页面
  • ✦ 进入页面前设置标题（document.title）
  • ✦ 离开页面前提示用户保存未提交的表单
  • ✦ 进入页面前预加载数据
📌 路由守卫分三类：全局守卫（所有路由都触发）/ 路由独享守卫（在路由配置中，只对该路由生效）/ 组件内守卫（在组件 options 中定义）
第二节

全局守卫

beforeEach — 全局前置守卫（最常用）

每次路由跳转前都会触发，可以在这里做权限验证。

// 在 router 实例上注册 router.beforeEach((to, from, next) => { // to：即将进入的路由对象（$route 的样子） // from：当前正要离开的路由对象 // next：函数，必须调用！决定导航如何继续 const isLoggedIn = localStorage.getItem('token') if (to.meta.requiresAuth && !isLoggedIn) { // 需要登录，但未登录 → 重定向到登录页 next({ path: '/login', query: { redirect: to.fullPath } }) } else { next() // 放行，继续导航 } })
next() 的几种调用方式
next() // ✅ 放行，继续正常导航 next(false) // ❌ 中断导航，留在当前页 next('/login') // 重定向到 /login next({ path: '/login' }) // 同上，对象写法 next(new Error('无权访问')) // 导航中断并触发 router.onError()
⚠️ 必须调用 next()！否则导航会永远停在那里，页面不跳转。这是新手最常见的错误。
afterEach — 全局后置钩子

路由跳转完成后触发，没有 next 参数（导航已经完成，无法改变了）。常用于修改页面标题、统计访问日志。

router.afterEach((to, from) => { // 根据路由 meta 设置页面标题 document.title = to.meta.title || '我的应用' // 埋点统计：记录用户访问了哪个页面 analytics.track('pageview', { path: to.path }) })
路由 meta 字段

在路由配置里可以附加自定义信息，在守卫中读取 to.meta 来判断：

routes: [ { path: '/admin', component: Admin, meta: { requiresAuth: true, // 需要登录才能访问 roles: ['admin'], // 需要的角色 title: '后台管理' // 页面标题 } }, { path: '/dashboard', component: Dashboard, meta: { requiresAuth: true, title: '仪表盘' } }, { path: '/login', component: Login, meta: { title: '登录' } // 不需要 requiresAuth } ]
第三节

路由独享守卫与组件内守卫

路由独享守卫（beforeEnter）

写在路由配置中，只对该路由生效，等同于 beforeEach 但作用域更小。

routes: [ { path: '/vip-page', component: VipPage, beforeEnter(to, from, next) { const user = store.getState().user if (!user.isVip) { next({ path: '/upgrade' }) // 非VIP跳到升级页 } else { next() } } } ]
组件内守卫

直接写在 Vue 组件的 options 中，有三个：

export default { name: 'EditArticle', // ① beforeRouteEnter：路由进入该组件前触发 // ⚠️ 此时组件还未创建，无法访问 this！ beforeRouteEnter(to, from, next) { next(vm => { // 通过回调访问组件实例（vm），此时组件已创建 vm.fetchArticle(to.params.id) }) }, // ② beforeRouteUpdate：同一路由，参数变化时触发（组件复用时） // 此时 this 可以用 beforeRouteUpdate(to, from, next) { this.fetchArticle(to.params.id) // 重新加载数据 next() }, // ③ beforeRouteLeave：离开该路由前触发 // 常用：用户有未保存的内容时，离开前提示 beforeRouteLeave(to, from, next) { if (this.hasUnsavedChanges) { const confirmed = window.confirm('有未保存的内容，确定要离开吗？') next(confirmed) // true 放行，false 取消 } else { next() } } }
第四节

完整导航解析流程

当一次路由跳转发生时，Vue Router 按以下顺序执行所有守卫：

1. 导航被触发（用户点击链接 / 调用 push） 2. 【组件内守卫】 在离开的组件里调用 beforeRouteLeave 3. 【全局守卫】 调用全局 beforeEach 4. 【路由独享守卫】如果目标路由配置了 beforeEnter，调用它 5. 【解析异步组件】（懒加载路由） 6. 【组件内守卫】 在被激活的组件里调用 beforeRouteEnter 7. 【全局守卫】 调用全局 beforeResolve 8. 导航被确认（navigation confirmed） 9. 【全局钩子】 调用全局 afterEach 10. 【DOM 更新】 触发 DOM 更新 11. 【组件内守卫】 beforeRouteEnter 的 next 回调被调用（组件实例已创建）
📌 记住顺序的口诀：离开组件守卫 → 全局前置守卫 → 路由独享守卫 → 进入组件守卫 → 全局解析守卫 → 导航确认 → 全局后置钩子
第五节

实战：登录鉴权完整方案

以下是真实项目中最常用的路由守卫鉴权方案：

// router/index.js import Vue from 'vue' import VueRouter from 'vue-router' import Home from '../views/Home.vue' import Login from '../views/Login.vue' import Admin from '../views/Admin.vue' Vue.use(VueRouter) const routes = [ { path: '/', component: Home, meta: { title: '首页' } }, { path: '/login', component: Login, meta: { title: '登录' } }, { path: '/admin', component: Admin, meta: { requiresAuth: true, title: '后台管理' } }, { path: '*', redirect: '/' } ] const router = new VueRouter({ mode: 'history', routes }) // 全局前置守卫：统一处理登录鉴权 router.beforeEach((to, from, next) => { // 设置页面标题 document.title = to.meta.title || 'My App' // 检查是否需要登录 if (to.meta.requiresAuth) { const token = localStorage.getItem('token') if (!token) { // 未登录 → 跳转登录页，记录目标地址 next({ path: '/login', query: { redirect: to.fullPath } }) } else { next() } } else { next() } }) export default router
// Login.vue 登录成功后跳回原目标页 methods: { async handleLogin() { await login(this.form) localStorage.setItem('token', 'xxx') // 读取登录前想去的地址，没有则去首页 const redirect = this.$route.query.redirect || '/' this.$router.replace(redirect) } }
第六节

守卫速查表

守卫位置触发时机this 可用常见用途
beforeEach全局每次路由跳转前❌（不在组件中）登录鉴权、权限检查
afterEach全局每次路由跳转后❌设置标题、统计埋点
beforeResolve全局确认导航前（所有守卫都解析完）❌数据预加载完成后放行
beforeEnter路由配置进入该路由前❌针对特定路由的权限
beforeRouteEnter组件内路由进入，组件创建前❌（用 next(vm)）进入前预加载数据
beforeRouteUpdate组件内参数变化，组件复用时✅参数变化时刷新数据
beforeRouteLeave组件内离开该路由前✅提示未保存内容
