Vue Router · 路由参数

25-2  |  params 动态路由 / query 查询参数 / props 解耦 / 参数传递对比

第一节

params 参数（动态路由段）

用 :参数名 定义动态路由段，访问 /user/42 时，42 会被捕获为 params.id。

路由配置
const router = new VueRouter({ routes: [ // :id 是动态段，匹配任意值 { path: '/user/:id', name: 'user', component: User }, // 多个动态段 { path: '/post/:year/:month', component: Post }, // 可选参数（? 表示可有可无） { path: '/article/:id?', component: Article }, ] })
传参
<!-- 声明式（模板中） --> <router-link :to="{ name: 'user', params: { id: 42 } }">用户详情</router-link> <!-- 生成地址：/user/42 --> // 编程式（JS 中） this.$router.push({ name: 'user', params: { id: 42 } })
接收参数
const User = { template: `<div> <h2>用户 ID：{{ $route.params.id }}</h2> </div>`, created() { // $route.params 是一个对象 console.log(this.$route.params.id) // "42"（字符串！） console.log(this.$route.params) // { id: "42" } } }
⚠️ 注意：params 只能配合命名路由（name）使用，不能配合 path 字符串 + params 一起用。
如果用 { path: '/user', params: { id: 42 } }，params 会被忽略！必须用 { name: 'user', params: { id: 42 } }。
同一路由，参数变化时组件不重建！

从 /user/1 跳转到 /user/2 时，Vue Router 为了性能会复用同一个组件，而不是销毁重建。这导致 created 等生命周期钩子不会重新触发。

// 解决方案1：用 watch 监听 $route watch: { '$route.params.id'(newId, oldId) { this.fetchUser(newId) // 参数变化时重新请求数据 } }, // 解决方案2：用 beforeRouteUpdate 导航守卫（更推荐） beforeRouteUpdate(to, from, next) { this.fetchUser(to.params.id) next() }
第二节

query 参数（查询字符串）

query 参数出现在 URL 的 ? 之后，如 /search?keyword=vue&page=2，不需要在路由配置中声明。

传参
<!-- 声明式 --> <router-link :to="{ path: '/search', query: { keyword: 'vue', page: 2 } }"> 搜索结果 </router-link> <!-- 生成地址：/search?keyword=vue&page=2 --> // 编程式 this.$router.push({ path: '/search', query: { keyword: 'vue', page: 2 } })
接收参数
const Search = { template: `<div> <p>搜索关键词：{{ $route.query.keyword }}</p> <p>当前页：{{ $route.query.page }}</p> </div>`, created() { console.log(this.$route.query) // { keyword: 'vue', page: '2' } // page 是字符串！需要 Number(this.$route.query.page) } }
params vs query 对比
对比项paramsquery
URL 形态/user/42/search?id=42
路由配置需要 :id 占位符无需配置，直接用
搭配必须配合 name可以配合 path 或 name
刷新后保留✅ 保留（在 URL 里）✅ 保留（在 URL 里）
适合场景资源标识（用户ID、文章ID等）可选过滤/排序参数（页码、关键词等）
语义标识"哪一条"资源过滤/查询条件
第三节

props 解耦（推荐写法）

默认写法需要在组件内写 this.$route.params.id，这让组件与路由强耦合——脱离路由就不能用这个组件了。
props 配置可以让组件接收路由参数就像接收普通 props 一样，完全解耦。

写法一：布尔值（props: true）—— 将 params 转为 props
// 路由配置 { path: '/user/:id', name: 'user', component: User, props: true } // 组件中：直接用 props 接收，不用写 $route.params const User = { props: ['id'], // id 直接来自路由 params template: '<div>用户ID：{{ id }}</div>' } // 等价于之前的： // template: '<div>用户ID：{{ $route.params.id }}</div>'
📌 props: true 只把 params 转成 props，不处理 query。
写法二：对象（props: {}）—— 传入静态 props
// 路由配置：传入固定的 props 值，不依赖路由参数 { path: '/promotion', component: Banner, props: { theme: 'holiday', discount: 0.8 } // 静态值 } const Banner = { props: ['theme', 'discount'], template: '<div>{{ theme }} 折扣：{{ discount }}</div>' } // 适合：给路由组件传入与路由无关的固定配置
写法三：函数（最灵活）—— 自定义映射
// props 是一个函数，接收 $route 对象，返回要传给组件的 props 对象 { path: '/search', component: SearchResult, props: route => ({ keyword: route.query.keyword, // 把 query 转为 props page: Number(route.query.page) || 1, // 顺便做类型转换 id: route.params.id // params 也可以 }) } const SearchResult = { props: ['keyword', 'page', 'id'], template: '<div>搜索：{{ keyword }}，第 {{ page }} 页</div>' } // 函数写法可以处理 query、params 和静态值，是最推荐的方式
三种写法对比
写法适用场景能处理
props: true路由只有 params 参数params → props
props: {}需要传入固定静态值静态值 → props
props: route => ()需要处理 query、类型转换等params + query + 静态 → props
第四节

完整 Demo：文章详情页

演示 params + query + props 三种参数方式的综合使用场景。

<!DOCTYPE html> <html><head><title>路由参数 Demo</title></head> <body> <div id="app"> <nav> <!-- params 传参 --> <router-link :to="{ name: 'article', params: { id: 1 } }">文章1</router-link> <router-link :to="{ name: 'article', params: { id: 2 } }">文章2</router-link> <!-- query 传参，同一个组件 --> <router-link :to="{ path: '/search', query: { kw: 'vue', page: 1 } }">搜索</router-link> </nav> <router-view></router-view> </div> <script src="../js/vue.js"></script> <script src="https://unpkg.com/vue-router@3.6.5/dist/vue-router.js"></script> <script> // 组件用 props 接收，与路由解耦 const Article = { props: ['id'], template: `<div> <h3>文章详情</h3> <p>文章 ID：{{ id }}（类型：{{ typeof id }}）</p> <p>$route.params：{{ $route.params }}</p> </div>` } const Search = { props: ['kw', 'page'], template: `<div> <h3>搜索结果</h3> <p>关键词：{{ kw }}，当前页：{{ page }}（类型：{{ typeof page }}）</p> <p>$route.query：{{ $route.query }}</p> </div>` } const router = new VueRouter({ routes: [ // props: true → params.id 作为 prop 传入 { path: '/article/:id', name: 'article', component: Article, props: true }, // props 函数 → query 也转成 prop，顺便做类型转换 { path: '/search', component: Search, props: route => ({ kw: route.query.kw, page: Number(route.query.page) || 1 }) } ] }) new Vue({ el: '#app', router }) </script> </body></html>

✅ 最佳实践：在团队/正式项目中，推荐给所有需要传参的路由配置 props，让组件不直接依赖 $route，提升组件的可复用性和可测试性。
