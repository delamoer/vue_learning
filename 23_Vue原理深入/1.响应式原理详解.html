  • Q1：Vue 2 响应式基于什么？

  • Q2：为什么对象新增属性不响应？

    答：批量合并更新，提升性能，避免重复渲染。

补充知识点

Object.freeze() — 跳过响应式劫持的性能优化

Vue 2 在初始化时会对 data 中的每个属性递归调用 Object.defineProperty 添加 getter/setter。 对于永远不会改变的大型静态数据（如省市区联动数据、静态配置表），这是纯粹的性能浪费。 使用 Object.freeze() 冻结对象后，Vue 检测到属性不可配置（configurable: false），会自动跳过劫持。 

// ❌ 有问题的写法：几千条城市数据全部被响应式劫持，浪费内存
data() {
  return {
    cityList: getCityData()  // 3000+ 条，每条都被 defineProperty
  }
}

// ✅ 正确做法：冻结静态数据，Vue 跳过劫持
data() {
  return {
    cityList: Object.freeze(getCityData())  // ✅ 不被响应化，节省内存+初始化时间
  }
}

// ✅ 也可以在 created 之前通过 this.$options 挂载（完全绕过响应式系统）
created() {
  // this.$options.staticData 不会被响应式处理
  this.$options.staticTableData = Object.freeze(largeDataset)
}

// ⚠️ 注意：冻结的对象不能再修改，以下操作会静默失败（严格模式下抛错）
const obj = Object.freeze({ a: 1 })
obj.a = 2   // 静默失败，obj.a 仍为 1
📈 实测效果（来自社区基准测试）：
包含 10000 条记录的列表，使用 Object.freeze 后初始化速度提升约 2-4 倍，内存占用减少约 30-50%。
适用场景：省市区数据、静态菜单配置、只读的接口数据（如字典表、枚举配置）。
