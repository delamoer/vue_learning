理解 new Vue() 内部发生了什么：初始化、编译、挂载、更新

  • 理解 _init、状态初始化、编译、挂载的先后关系

🗺️ 总流程（高频面试答案）

1. new Vue
执行构造函数，进入 _init
2. 合并选项
处理全局配置、组件配置、实例配置
3. 初始化状态
props/methods/data/computed/watch
4. 编译模板
template 转 render（如需）
5. 挂载渲染
mount -> watcher -> patch 到 DOM
一句话：先把“能力”准备好（数据/方法/响应式），再把“视图”渲染到页面。

📘 Demo 2：选项合并与状态初始化

为什么 data 是函数？为什么 methods 可以直接用？
data 初始化：
读取 data 结果对象，代理到 vm 上，并做响应式处理。
methods 初始化：
把方法挂到 vm，自动绑定 this 到实例。
computed 初始化：
创建惰性 watcher，按需计算并缓存。
watch 初始化：
创建用户 watcher，侦听指定数据变化。
组件中 data 必须是函数，避免多个实例共享同一对象。

📘 Demo 3：模板编译与挂载时机

有 render 就用 render；没有则尝试编译 template
if (!options.render) { // runtime+compiler 才能做这步 options.render = compileToFunctions(options.template) } mountComponent(vm, el) // 创建渲染 watcher，首次 patch
脚手架常用 runtime-only：编译在构建阶段完成，运行时直接执行 render。

📘 Demo 5：常见误区与排查

  • 误区1：created 可以拿到 DOM（错误）
  • 误区2：每次 set data 都会立刻重绘（错误，异步批处理）
  • 误区3：runtime-only 也能直接在线编译 template（错误）
  • 误区4：组件 data 写对象没问题（错误，会共享状态）
排查思路：先确认版本构建类型，再确认生命周期时机，最后检查响应式边界。

📘 Demo 6：面试速答 + 练习

  • Q1：new Vue 后做了什么？
    答：_init -> 合并选项 -> 初始化状态/生命周期/事件 -> 编译(可选) -> 挂载 -> 渲染 watcher。
  • Q2：为什么模板有时不能用？
    答：runtime-only 不带编译器，需预编译成 render。
  • Q3：首屏渲染和后续更新核心差异？
    答：首屏是首次 patch，后续是响应式驱动 watcher 触发 patch。
