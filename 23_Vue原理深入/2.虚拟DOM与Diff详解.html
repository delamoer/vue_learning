📘 Demo 1：虚拟 DOM 是什么

真实 DOM 太重，先在 JS 里构建轻量 VNode
// 一个简化 VNode { tag: 'li', key: 'u_1', data: { class: 'row' }, children: [ { tag: undefined, text: '张三' } ] }
核心：Vue 先生成“新旧两棵 VNode 树”，再 diff，最后只把“差异”打到真实 DOM。

📘 Demo 3：key 的作用（正确）

使用稳定 key，Diff 能正确复用与移动节点
{{ user.name }} key: {{ user.id }}
当 key 稳定时，Vue 更可能执行“移动节点”而不是“销毁重建”。

📘 Demo 4：index 作为 key 的风险

错误示例：index key 导致状态错位
{{ idx }}. {{ task.title }} key: index
当在头部插入时，后续项 index 全变，旧节点可能被错误复用，输入框/组件内部状态容易错位。

📘 Demo 5：Diff 规则速记

Vue 2 Diff 关键点（面试可直接说）： 1) 同层比较，不做跨层级暴力比对（降低复杂度） 2) 先比较节点类型（tag / key），不同则直接替换 3) 列表更新依赖 key，key 稳定可提升复用率 4) 通过 patch 仅更新必要 DOM，而非整棵重建
理解方式：Diff 的目标不是“找最优编辑距离”，而是“在工程可接受复杂度下尽量快”。

📘 Demo 6：面试高频问答 + 自测

  • Q1：为什么需要虚拟 DOM？
    答：把直接 DOM 操作抽象成 JS 对象比较，减少不必要真实 DOM 变更，便于跨平台渲染。
  • Q2：Diff 一定比直接操作 DOM 快吗？
    答：不绝对；小规模手写精准 DOM 可能更快，但框架场景下 Diff 提供稳定工程收益。
  • Q3：key 为什么重要？
    答：key 决定节点身份，影响复用与移动策略；不稳定 key 会导致性能与状态问题。
