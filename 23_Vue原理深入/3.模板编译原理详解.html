🧩 23.3 模板编译原理详解

从 template 到 render：Parse → Optimize → Generate

🎯 本节目标

  • 搞清楚 template 为什么不能直接渲染
  • 理解编译三阶段：解析、优化、代码生成
  • 能解释“运行时版 vs 完整版（含编译器）”

🗺️ 编译总流程

1. Parse
把模板字符串解析为 AST（抽象语法树）
2. Optimize
标记静态节点，减少重复 patch
3. Generate
把 AST 生成为 render 函数字符串
4. Render
执行 render 返回 VNode，再 patch 到 DOM
一句话：模板是“写给人看的”，render 是“写给引擎跑的”。

📘 Demo 4：运行时版 vs 完整版

为什么有些项目里不能写 template 字符串？
运行时版（runtime-only）不带编译器：需要你提前把模板编译成 render（通常由构建工具完成）。
完整版（runtime + compiler）可以在浏览器里把 template 编译成 render，但包体积更大。
// runtime-only（常见于脚手架生产构建） new Vue({ render: h => h(App) }) // runtime + compiler（可直接写 template） new Vue({ template: '' })

📘 Demo 5：常见坑与排查

  • 模板根节点必须唯一（Vue 2）
  • 不要在模板里写过重表达式，复杂逻辑放到 computed
  • 避免把会变化的数据写死进静态结构，影响优化收益
  • 列表渲染配合稳定 key，让 Diff 更高效

📘 Demo 6：面试高频问答 + 练习

  • Q1：template 到页面经历了什么？
    答：template → AST → render 函数 → VNode → patch 到真实 DOM。
  • Q2：静态节点优化做了什么？
    答：标记静态子树，后续更新跳过，减少不必要 patch。
  • Q3：为什么有 runtime-only？
    答：减小体积、提升运行时性能，编译前移到构建阶段。

🧪 练习任务（40-60 分钟）

  2. 把一个简单模板手写成 render 形式（用 _c/_v/_s 思路）。
  3. 对一个列表页面标注哪些节点可视为静态节点，解释为什么。
