第一节

项目文件地图：每个文件/目录的职责

vue2-sfc-demo/
│
├── public/← 静态资源，原样复制，不经过 Webpack 处理
│ ├── index.html← ★ 整个应用的唯一 HTML 壳，浏览器真正加载这个
│ └── favicon.ico← 浏览器标签页左上角的小图标
│
├── src/← 你写的所有源码，Webpack 从这里开始编译
│ ├── main.js← ★ 程序入口/点火器，Webpack 的起点
│ ├── App.vue← ★ 根组件，整个组件树的顶端
│ ├── assets/← 图片/字体等资源（会被 Webpack 处理，可优化）
│ └── components/← 子组件存放处（HelloCard.vue 等）
│
├── package.json← ★ 项目说明书：依赖清单 + 命令表 + ESLint 配置
├── babel.config.js← JS 语法降级规则（ES6+ → ES5）
├── vue.config.js← 覆盖 Vue CLI 内置 Webpack 配置的地方
├── jsconfig.json← 只给 VS Code 编辑器看的，提供路径别名等智能提示，不影响编译
└── .gitignore← 告诉 Git 哪些文件/目录不提交（如 node_modules/）
📌 最重要的 4 个文件：public/index.html（壳）、src/main.js（点火器）、src/App.vue（根组件）、package.json（项目配置中心）
第二节

逐文件精讲：它是什么 + 为什么需要它

📄 package.json 项目中枢

{ "name": "vue2-sfc-demo", "scripts": { "serve": "vue-cli-service serve", // npm run serve → 启动开发服务器 "build": "vue-cli-service build", // npm run build → 打包生产版本 "lint": "vue-cli-service lint" // npm run lint → 检查代码风格 }, "dependencies": { "core-js": "^3.8.3", // Babel 降级时填充缺失的浏览器 API（如 Promise） "vue": "^2.6.14" // Vue 框架本体，打包后随代码一起发布给用户 }, "devDependencies": { "@vue/cli-service": "~5.0.0", // Vue CLI 核心，封装了 Webpack + Dev Server "@vue/cli-plugin-babel": "~5.0.0", // Babel 插件，负责 JS 语法降级 "@vue/cli-plugin-eslint": "~5.0.0", // ESLint 插件，负责代码风格检查 "vue-template-compiler": "^2.6.14" // ★ 编译 .vue 的 <template> 为 render 函数 }, "browserslist": ["> 1%", "last 2 versions", "not dead"] // Babel 根据这个决定要把代码降到哪个 ES 版本 }

注意 dependencies 和 devDependencies 的区别：

dependencies（生产依赖）

打包后的代码仍然需要它，会被打进最终的 bundle.js。
例：vue、vue-router、axios

devDependencies（开发依赖）

只在开发/构建阶段用，不会出现在用户浏览器中。
例：webpack、babel、eslint、vue-loader

🌐 public/index.html HTML 模板

<body> <div id="app"></div> <!-- built files will be auto injected --> </body>

这是浏览器真正加载的那个 HTML 文件。它只是个"壳"，核心就是 <div id="app">。构建时 HtmlWebpackPlugin 会自动把 <script src="app.xxxxxxx.js"> 注入进来。

<!-- 模板里还有两个 EJS 语法的占位符，构建时自动替换 --> <link rel="icon" href="<%= BASE_URL %>favicon.ico"> <!-- 等价于：href="/favicon.ico" --> <title><%= htmlWebpackPlugin.options.title %></title> <!-- 等价于：<title>vue2-sfc-demo</title>（取自 package.json 的 name）-->
💡 public/ 目录下的文件会被原样复制到构建产物里，Webpack 不处理它们。如果你把图片放在 public/ 里，引用时写 /logo.png 即可；放在 src/assets/ 里，Webpack 会处理并优化（比如小图片自动 base64 内嵌）。

🔥 src/main.js 程序入口

import Vue from 'vue' // 1. 引入 Vue 框架 import App from './App.vue' // 2. 引入根组件 Vue.config.productionTip = false new Vue({ render: h => h(App), // 3. 告诉 Vue 把 App.vue 渲染出来 }).$mount('#app') // 4. 找到 index.html 里的 <div id="app"> 并接管它

这是 Webpack 的编译起点（entry point）。整个组件树从这里出发。

🔡 babel.config.js 语法降级

module.exports = { presets: ['@vue/cli-plugin-babel/preset'] // 使用 Vue CLI 推荐的 Babel 预设 // 它会根据 package.json 里的 browserslist， // 自动决定把哪些现代语法转成 ES5 }

举例：你写了 async/await、可选链 a?.b、空值合并 a ?? b，Babel 会把它们转成 IE 或旧版安卓能跑的 ES5 代码。

// 你写的（现代语法） const name = user?.getName() ?? '匿名' // Babel 转换后（ES5 兼容语法） var _user; var name = ((_user = user) === null || _user === void 0 ? void 0 : _user.getName()) !== null && ... || '匿名'

⚙️ vue.config.js Webpack 覆盖

const { defineConfig } = require('@vue/cli-service') module.exports = defineConfig({ transpileDependencies: true // 让 Babel 也处理 node_modules 里的依赖 // 某些第三方包只提供 ES Module 语法，部分浏览器运行会报错，开启此项可解决 })

Vue CLI 内置了一套完整的 Webpack 配置，通常不需要手写 webpack.config.js。如果需要微调，就在这里写。常见用法：

const { defineConfig } = require('@vue/cli-service') module.exports = defineConfig({ devServer: { port: 3000, // 改开发服务器端口（默认8080） proxy: { // 配置接口代理，解决跨域问题 '/api': { target: 'http://localhost:8888' } } }, publicPath: '/my-app/', // 部署到子路径时使用 outputDir: 'dist', // 打包输出目录（默认 dist/） })
第三节

.vue 文件如何被编译？核心：vue-loader

浏览器完全不认识 .vue 文件。Webpack 通过 vue-loader 把它拆成三部分分别处理，最终合成一个 JS 模块：

HelloCard.vue （你写的源码）
│
├── <template> ──────────→ vue-template-compiler ──→ render() 函数
│ HTML 标记语言 把模板编译成 JS 渲染函数 浏览器能直接调用
│
├── <script> ──────────→ babel-loader ──→ ES5 模块对象
│ 组件的逻辑（data/methods/...） 降级 + 模块化处理
│
└── <style scoped> ──────→ css-loader + style-loader ──→ 注入 + hash 隔离
CSS 样式 提取样式，加 data-v-xxx 属性

↓ 三部分合并 ↓

{ render: fn, data: fn, methods: {...}, __scopeId: 'data-v-7ba5bd' }
// 一个标准的 Vue 组件选项对象，可以被 new Vue() 或其他组件使用
三个 Loader 的职责
Loader / 插件 处理对象 做了什么 结果
vue-template-compiler <template> 把 HTML 模板编译成 JavaScript 的 render() 函数 render 函数
babel-loader <script> 把 ES6+ 语法（箭头函数、class、async等）转成 ES5，所有浏览器都能跑 ES5 模块
css-loader <style> 解析 CSS 中的 @import、url()，处理模块依赖 CSS 字符串
style-loader CSS 字符串 把 CSS 字符串动态注入到页面 <head> 的 <style> 标签里 运行时注入样式
vue-loader（统筹） 整个 .vue 文件 拆分 template/script/style 三块，分别调用上面的 loader，最后合并为一个 JS 模块 组件对象
HtmlWebpackPlugin public/index.html 读取 HTML 模板，构建完成后把生成的 JS/CSS 的 <script>/<link> 标签自动注入进去 最终 index.html
💡 你在 package.json 的 devDependencies 里看不到单独列出 webpack、vue-loader、style-loader 等，是因为它们已经被 @vue/cli-service 内部依赖并管理，Vue CLI 帮你屏蔽了这些复杂性。
第四节

完整启动流程：从 npm run serve 到浏览器看到页面

1

执行 npm run serve

npm 查找 package.json 的 scripts.serve，实际运行：vue-cli-service serve
这启动了 @vue/cli-service，它是对 Webpack 的封装，带有热更新（HMR）功能。

2

读取配置文件，合并 Webpack 配置

cli-service 读取：vue.config.js（用户自定义）、babel.config.js（Babel 规则）、package.json 里的 browserslist 和 eslintConfig，合并成最终的 Webpack 配置对象。

3

从入口 src/main.js 开始，递归分析依赖

Webpack 读取 main.js，发现它 import App from './App.vue'，于是去处理 App.vue。App.vue 又 import 了 HelloCard.vue，如此递归，直到分析出所有依赖，形成一棵"依赖树"（模块图）。

4

用对应的 Loader 处理每个文件

遇到 .vue 文件 → vue-loader 拆分 + 分别处理
遇到 .js 文件 → babel-loader 降级
遇到 .css 文件 → css-loader + style-loader
遇到图片 → url-loader / asset module（小图转 base64，大图复制并改名）

5

打包成 bundle 文件，注入 index.html

所有模块打包成（开发时放内存里，不写磁盘）：
app.[hash].js：你写的业务代码
chunk-vendors.js：第三方库（Vue 框架本体等）
HtmlWebpackPlugin 把这两个 <script> 标签自动插入 index.html。

6

Dev Server 监听 localhost:8080

Webpack Dev Server 起来了，开始监听文件变化。你访问 http://localhost:8080，它把内存里的 index.html 返回给浏览器。

7

浏览器执行 JS，Vue 接管 DOM

浏览器加载 index.html → 执行 chunk-vendors.js（Vue 就绪）→ 执行 app.js → 运行 main.js 的代码 → new Vue().$mount('#app') → Vue 用 App.vue 的 render() 函数替换掉那个空 <div id="app"> → 页面渲染出来。

8

热模块替换（HMR）：改代码不用刷页面

你修改并保存任意 .vue 文件 → Webpack 重新编译改动的模块 → 通过 WebSocket 通知浏览器 → 浏览器只替换受影响的模块，不刷新整页，状态保存。

第六节

npm run build 和 npm run serve 有什么不同？

对比项npm run serve（开发）npm run build（生产）
构建产物存放 内存（不写磁盘，速度快） 磁盘 dist/ 目录
文件名 app.js（无 hash） app.3a8f6c.js（带内容 hash，浏览器缓存控制）
代码压缩 不压缩（方便调试） 压缩混淆（terser），体积大幅减小
Source Map 生成（方便调试） 默认不生成（可配置）
Tree Shaking 不优化 移除未使用的代码
图片处理 原样 小图自动 base64 内嵌，大图带 hash 重命名
热更新 HMR 有（保存即更新） 无
# 打包后的 dist/ 目录结构 dist/ ├── index.html # 已注入 <script> 标签的最终 HTML ├── favicon.ico # 从 public/ 复制过来 └── js/ ├── app.3a8f6c12.js # 你的业务代码（压缩混淆） ├── app.3a8f6c12.js.map # Source Map（可选） └── chunk-vendors.9b2e4f.js # Vue 等第三方库（长缓存）
💡 dist/ 里的内容就是你上传到服务器的东西。服务器只需要能静态托管这些文件（Nginx、Apache、GitHub Pages 都行），不需要安装 Node.js。
总结

面试速答：常见问题

Q：Vue CLI 和 Webpack 是什么关系？
Vue CLI 是对 Webpack 的封装。它内置了一套合理的 Webpack 配置（处理 .vue、Babel 降级、CSS 提取等），让你不用手写 webpack.config.js，用 vue.config.js 做覆盖就够了。
Q：浏览器能直接运行 .vue 文件吗？
不能。浏览器只认识 HTML / CSS / JS。.vue 文件在构建阶段被 vue-loader 编译成标准 JS 模块，你在浏览器里看到的 .vue 文件已经消失了，全部变成了 app.js。
Q：main.js 里的 $mount('#app') 是什么意思？
找到 public/index.html 里的 <div id="app"> 这个 DOM 元素，用 Vue 的组件树替换它的内容。这是 Vue 应用"接管"页面的时刻。
Q：public/ 和 src/assets/ 里的文件有什么区别？
public/ 里的文件原样复制，Webpack 不处理，用绝对路径 /filename 引用。src/assets/ 里的文件会被 Webpack 处理：小图转 base64 内嵌、大图 hash 重命名、路径自动追踪，适合组件直接 import 的资源。
Q：为什么 node_modules 很大但不提交到 Git？
node_modules 里是根据 package.json 安装的依赖，别人拿到代码后执行 npm install 就能重建。它通常有几百 MB，提交没意义且很慢，所以 .gitignore 里排除了它。
第七节

如果用 Vite 会怎样？—— Vite vs Vue CLI 全面对比

Vite 是目前（2024+）的主流选择，Vue 3 官方默认推荐。它用了一套和 Webpack 完全不同的工作原理，开发体验差异巨大。

核心原理差异
⚙️ Vue CLI（Webpack）

启动时把所有文件全部打包成一个（或几个）bundle.js，再启动 Dev Server。

项目越大，启动越慢——因为每次都要把全部代码过一遍 Webpack 的编译流水线。

改一个文件 → 重新编译受影响的 chunk → 通过 HMR 推送给浏览器。

⚡ Vite（原生 ESM）

启动时完全不打包，直接启动 Dev Server（几乎瞬间）。

浏览器请求哪个文件，Vite 就实时编译那一个文件，用浏览器原生 ESM（type="module"）加载。

改一个文件 → 只重新编译那一个文件 → 推送给浏览器，HMR 极快。

index.html 内容的差异
Vue CLI 的 public/index.html

package.json 命令对比
Vue CLI
"scripts": { "serve": "vue-cli-service serve", "build": "vue-cli-service build", "lint": "vue-cli-service lint" }
Vite
"scripts": { "dev": "vite", // 注意是 dev！不是 serve "build": "vite build", "preview": "vite preview" // 预览生产包，Vue CLI 没有 }

工作流程对比（一图理解本质差异）
【Webpack Dev Server 启动流程】 npm run serve ↓ 全量打包：src/ 下所有文件 → Webpack 一次性编译所有模块 → 生成 bundle.js（放内存） ↓ ⏱ 耗时：几秒到几十秒（项目越大越慢） ↓ Dev Server 就绪，浏览器加载一个大 bundle.js 【Vite Dev Server 启动流程】 npm run dev ↓ 不打包！直接启动 Dev Server（<1s） ↓ 浏览器加载 index.html → 遇到 <script type="module" src="/src/main.js"> ↓ 浏览器请求 /src/main.js → Vite 实时编译该文件 → 返回编译后的 JS ↓ 浏览器解析 import 语句 → 继续请求 /src/App.vue → Vite 实时编译 → 返回 ↓ 每个 .vue 文件按需、独立编译，未访问到的文件完全不编译
🧠 一句话理解核心差异：Webpack 是"先把所有食材全部备好再开始做饭"；Vite 是"客人点什么菜，现做什么菜"。餐厅越大（项目越复杂），Vite 的优势越明显。
为什么本机用不了 Vite

Vite 在开发环境依赖 esbuild（一个用 Go 语言编写的原生可执行文件）。
本机有 AppLocker / 组策略，禁止运行 node_modules 目录下的 .exe 文件。
因此 node_modules/@esbuild/win32-x64/esbuild.exe 被系统拦截，报错 spawn UNKNOWN。

Vue CLI（Webpack）完全用 JavaScript 编写，不依赖任何原生 .exe 文件，所以能正常运行。
这是我们选择 Vue CLI 的唯一原因——性能上 Vite 更好，但环境限制决定了只能用 Webpack。

在无限制环境中如何创建 Vite + Vue 3 项目
# 方式一：npm create（官方推荐，交互式引导） npm create vue@latest my-app # 可选：TypeScript、Router、Pinia、ESLint 等 # 方式二：直接指定 Vite 模板 npm create vite@latest my-app -- --template vue # 进入项目 cd my-app npm install npm run dev # ← 注意是 dev，不是 serve！
