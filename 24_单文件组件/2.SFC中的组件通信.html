Demo 2

props + $emit：标准父子通信

CDN 与 SFC 写法对比——API 完全一样，只是文件结构不同：

CDN 写法（单文件 HTML）
// 直接在 components 选项里写 Vue.component('my-list', { template: `<ul>...</ul>`, props: ['items'] })
SFC 写法（.vue 文件）
// MyList.vue export default { name: 'MyList', props: ['items'] } // 在父组件 import 后局部注册
子组件完整示例（CounterBox.vue）
src/components/CounterBox.vue
<template> <div class="box"> <p>{{ label }}：{{ count }}</p> <button @click="add">+1</button> <button @click="reset">重置</button> </div> </template> <script> export default { props: { label: { type: String, default: '计数' }, // 带类型校验 step: { type: Number, default: 1 } // 带默认值 }, data() { return { count: 0 } }, methods: { add() { this.count += this.step; this.$emit('change', this.count) }, reset() { this.count = 0; this.$emit('reset') } } } </script>
父组件使用
src/App.vue（节选）
<template> <!-- 传 props，监听 $emit 事件 --> <CounterBox label="购物车数量" :step="2" @change="onCountChange" @reset="onReset" /> </template> <script> import CounterBox from './components/CounterBox.vue' export default { components: { CounterBox }, methods: { onCountChange(val) { console.log('新value:', val) }, onReset() { console.log('已重置') } } } </script>
⚠️ Props 单向数据流：子组件永远不要直接修改 prop（如 this.label = 'x'）。如需修改，用 $emit 通知父组件，由父来更新数据。

自定义组件的 v-model

让自己写的组件也能用 v-model，本质是 :value + @input 的语法糖。

v-model 拆解
<!-- 这两种写法完全等价 --> <MyInput v-model="searchText" /> <MyInput :value="searchText" @input="searchText = $event" />
实现支持 v-model 的输入组件（MyInput.vue）
src/components/MyInput.vue
<template> <div class="input-wrap"> <input :value="value" <!-- ① 接收父传来的值 --> @input="$emit('input', $event.target.value)" <!-- ② 修改时通知父 --> v-bind="$attrs" <!-- 透传 placeholder 等原生属性 --> /> <span v-if="value" @click="$emit('input', '')">✕</span> </div> </template> <script> export default { // 关键：声明接收 value prop，不要用 inheritAttrs 自动绑定到根元素 inheritAttrs: false, props: { value: String } } </script>
父组件使用
<MyInput v-model="keyword" placeholder="搜索..." /> <!-- placeholder 通过 $attrs 透传给原生 input -->
model 选项：自定义 prop 和 event 名
export default { // 默认 v-model = :value + @input // 用 model 选项可以自定义： model: { prop: 'checked', // 将 :checked 作为绑定值 event: 'change' // 将 @change 作为更新事件 }, props: { checked: Boolean } // 适用于自定义 checkbox/switch 组件 }
💡 Vue 3 把 v-model 升级了：默认绑定变成 modelValue + update:modelValue，并支持多个 v-model（如 v-model:title）。学 Vue 2 时理解原理，到 Vue 3 迁移很自然。

provide / inject：跨层级传值

解决 prop drilling（多层 props 层层透传）的问题，祖先直接把数据注入到任意后代。

场景：主题色需要传给 3 级以下的按钮组件
// ❌ prop drilling 的痛苦 <App :theme="theme"> <Layout :theme="theme"> <!-- Layout 自己不用，只是转发 --> <Sidebar :theme="theme"> <!-- Sidebar 自己不用，只是转发 --> <NavButton :theme="theme" /> <!-- 真正用的地方 --> </Sidebar> </Layout> </App>
provide — 祖先提供
App.vue（或任意祖先组件）
export default { data() { return { theme: 'dark' } }, // ✅ 方式一：对象形式（静态值，不响应式） provide: { appTheme: 'dark' }, // ✅ 方式二：函数形式（可访问 this，但仍非响应式） provide() { return { appTheme: this.theme, // 取当时的值，后续不更新 themeObj: this.$data // 传对象引用可实现响应式（技巧） } } }
inject — 后代注入
NavButton.vue（任意深度后代）
export default { // 简写：直接注入，变量名与 provide 的 key 一致 inject: ['appTheme'], // 完整写法：设置别名和默认值 inject: { theme: { from: 'appTheme', // 注入源的 key default: 'light' // 祖先没有提供时的默认值 } } // 模板中直接用 {{ theme }} }
⚠️ Vue 2 的 provide/inject 默认不是响应式的。如需响应式，可传入 Vue.observable() 包装的对象，或改用 Vuex。Vue 3 中 provide 可配合 ref/reactive 实现响应式。

$refs 与 Event Bus

$refs：直接访问子组件实例
父组件
<template> <!-- 给子组件打标记 --> <VideoPlayer ref="player" /> <button @click="$refs.player.play()">播放</button> <button @click="$refs.player.pause()">暂停</button> <!-- ref 也可以绑在原生 DOM 上 --> <input ref="searchInput" /> <button @click="$refs.searchInput.focus()">聚焦</button> </template>
⚠️ $refs 只在 mounted 后可用；v-if 条件为 false 时 $refs.xxx 是 undefined。不要在 created 里用。
Event Bus：非父子组件通信
src/event-bus.js（新建）
import Vue from 'vue' // 空 Vue 实例作为全局事件总线 export const EventBus = new Vue()
ComponentA.vue（发送方）
import { EventBus } from '../event-bus.js' methods: { notifyAll() { EventBus.$emit('user-login', { name: 'Alice' }) } }
ComponentB.vue（接收方）
import { EventBus } from '../event-bus.js' mounted() { EventBus.$on('user-login', this.handleLogin) }, beforeDestroy() { // ⚠️ 必须在销毁前解绑，否则内存泄漏！ EventBus.$off('user-login', this.handleLogin) }, methods: { handleLogin(user) { console.log('收到登录:', user) } }
🎯 Event Bus 适合小型项目快速通信。项目稍大就应换 Vuex（官方状态管理）——它有明确的数据流和 DevTools 支持，Event Bus 的事件链路难以追踪。

面试速答 + 练习任务

高频面试题
  • Q：Vue 2 父子组件通信有哪些方式？
    ① props 父传子；② $emit 子传父；③ v-model（:value + @input）；④ $refs 父直接访问子实例；⑤ $parent/$children（不推荐，耦合强）。
  • Q：为什么不能直接修改 props？
    Vue 的单向数据流原则：数据由父流向子，子组件修改 prop 不会影响父的数据源，却可能让数据流难以追踪。正确做法是通过 $emit 通知父组件，由父来决定是否更新。
  • Q：v-model 在组件上的原理？
    <MyInput v-model="x"> 等价于 <MyInput :value="x" @input="x = $event">。子组件通过 props: { value } 接收，通过 $emit('input', newVal) 更新。可用 model 选项自定义 prop 和 event 名。
  • Q：provide/inject 为什么不推荐大量使用？
    ① Vue 2 中默认非响应式，数据更新不会自动同步；② 数据来源不透明，组件间隐式耦合，难以维护；③ 大量共享状态应使用 Vuex，数据流清晰可追踪。provide/inject 适合组件库内部使用。
  • Q：Event Bus 使用时有什么注意事项？
    必须在 beforeDestroy 中调用 EventBus.$off 解绑事件，否则组件销毁后监听仍然存在，导致内存泄漏和重复触发。解绑时要传入相同的函数引用（不能用匿名函数）。
  • Q：SFC 中如何做到局部注册 vs 全局注册？
    局部：在 components: { MyComp } 中声明，只在当前组件可用；全局：在 main.js 中 Vue.component('MyComp', MyComp)，整个应用可用但打包体积不能按需优化。推荐局部注册。
